# EhBot 使用说明

本文是逐项功能与配置的详细说明。只想把服务跑起来请看 [README.md](../README.md)；
开发者内部约束在 [AgentHelp/AGENTS.md](../AgentHelp/AGENTS.md)。

## Web 界面

界面按「工作台 / 候选 / 活动 / 已下载 / 运行日志 / 设置」六个域组织，所有页面共用一套外壳与组件样式，没有构建步骤（HTMX 与 Alpine.js 直接随仓库分发）。

| 域 | 路径 | 子页 |
|----|------|------|
| 工作台 | `/` | 待办摘要、队列概况、启动异常 |
| 候选 | `/candidates` | 待审核、全部、需要补充信息、已通过、已驳回、失败，外加「手动添加」 |
| 活动 | `/activity` | 队列、打包、历史 |
| 已下载 | `/downloaded` | 全部、待打包、已打包、需干预、打包失败 |
| 运行日志 | `/logs` | 单页；级别下限是筛选，不是子页 |
| 设置 | `/settings` | 外部连接、来源规则、自动审批、归档、路径、AI 供应商、密码库、系统 |

- **旧地址仍可用**：早期版本的独立页面（`/connections`、`/sources`、`/downloads`、`/archive-settings`、`/auto-approval-rules` 等）一律 `307` 重定向到对应的新页面，书签不会失效。
- **候选与活动的每个筛选、排序、分页都在 URL 里**，因此任何一个视图都可以直接收藏或分享给另一台机器上的自己。
- **主题与密度存在浏览器本地**（`localStorage`），不入库：它回答的是「这块屏幕看起来怎样」，而不是「这个部署怎么运行」——服务端存主题会让操作者换一块屏幕后看到错的配色。
- **会花钱或不可撤销的操作会先问一次**：取消任务、驳回候选、切换停滞种子的来源、用 ExHentai Archive Download 取原档（消耗 GP）、断开外部连接、删除密码条目。重试、继续、暂停、通过、停止做种仍然一次点击——给每个按钮都加确认，只会让人不读就关掉。
- **封面尚未到达时显示骨架屏**：缩略图走本地代理且按需加载，先占好 2:3 的位置再补上图片，因此列表不会在图片陆续到达时跳动。

### 系统设置

「设置 → 系统」的五项运行参数存在数据库里，改完下一次请求即生效，**不需要重启、也不写进 `.env`**：

- **来源并发上限**（1–16）：预览页图片的同时抓取数。这是进程里唯一真正的并发闸门（两个作业工作器都是一次只领一个任务），`TELEGRAPH_CONCURRENCY` 只提供初始值。
- **轮询间隔**（500 ms–60 s，默认 2000 ms）：事件流是页面更新的主通道，轮询只是反向代理缓冲事件流时的兜底；后台标签页自动降到 15 s，无需单独设置。
- **自动审批扫描间隔**（0–1440 分钟，默认 30）：后台按这个间隔把待审核队列过一遍规则，`0` 表示只在候选入库时触发。规则命中与否不再取决于有没有人打开「待审核」页——那只是顺手多跑一次。每一轮扫描会**先把这一批缺元数据的候选补齐**再套规则：规则读的就是元数据，拿没刮过的候选去比对不叫「没命中」，叫没有依据。
- **时区**：时间戳按哪个 IANA 时区显示。只校验名字的形状而不比对 `zoneinfo` 列表——精简镜像可能完全不带 tz 数据库，而真正渲染时间的浏览器一定有完整列表。
- **日志等级**：走 `LOG_LEVEL` 同样的级别白名单（调试 / 信息 / 警告 / 错误），保存在数据库里，**保存后立即重建当前进程的日志门槛**，不用重启；切到「调试」会同时打开 uvicorn 访问日志。进程第一次启动、库里还没有这一项时，级别退回环境变量 `LOG_LEVEL`（默认 `INFO`）——`LOG_LEVEL` 依然是排查「页面起来之前」的启动失败用得上、也只能走的那条路（见「日志」一节）。

缺失的设置项等于「用默认值」，读取永不抛错；写入则是严格的一半，拒绝时当场说明原因。

### 自动审批规则

「设置 → 自动审批」编辑规则本身：每条规则由若干**字段条件**组成，每个条件自己挑字段、运算符和值，整条规则按 AND / OR 组合。

- **条件数量不限**。编辑器默认给三行，「添加条件」可以一直加下去，多余的行留空即忽略。没有 JavaScript 时也能用：页面永远比规则多渲染一行，保存后重新打开又多一行，逐次加一条即可。
- **「移除」等于把该行字段留空**，因此它的行为和手动清空完全一致。
- **保存前先「试跑」**，可对历史候选看这条规则会命中什么，试跑只读不写、不会顺手通过任何东西。
- **「取消编辑」回到本页**，放弃这次修改，规则本身不受影响。

每个条件是一行**类 SQL 表达式**，字段、运算符、值各占一列；运算符与写法不区分大小写（`NOT LIKE`、`not like`、`Not Like` 等价，`Exists` 与 `EXISTS` 相同）。DSL 预览与磁盘上保存的是同一份 AST 的同一渲染函数，不会出现两套说法。

- **字段角色决定可用运算符**：
  - 文本字段（标题、艺人、团体等）：`=`、`<>`、`LIKE`、`NOT LIKE`、`IN`、`NOT IN`、`EXISTS`（非空）、`NOT EXISTS`（为空）。
  - 数值字段（`Rating`、`Pages`）：上述之外再支持 `>`、`>=`、`<`、`<=`，比较按数值进行——`Rating = 4` 会命中 `4.0`；在文本字段上选这些运算符会被拒绝。
  - `TAG`（伪字段，匹配标签集合）：`EXISTS` / `NOT EXISTS`（必须带一个标签，意为「含 / 不含该标签」）、`IN` / `NOT IN`（含任意一个 / 一个都不含）、`LIKE` / `NOT LIKE`（任一标签名匹配通配符）。
- **`LIKE` 通配符**：`%` 匹配任意多个字符，`_` 匹配恰好一个字符；要匹配字面的 `%` 或 `_`，用 `[%]`、`[_]` 包起来。`{Title} not like "%miku%"` 命中标题里含 miku 的书。
- **匹配内容默认不区分大小写**（`%Miku%` 与 `%miku%` 互为命中），每条规则可在最下方单独勾选「区分大小写」关掉这个默认——开关**逐条生效**、不全局共享，数值比较不受影响。
- **`TAG` 的「全部包含」写成多个 `EXISTS` 条件用 AND 连**。例如「标题含 miku 但标签没有 NTR」：条件 `{Title} not like "%miku%"`（连接 AND）+ 条件 `{TAG} not Exists("NTR")`。「试跑」与「保存」读的是同一份条件行结构，「区分大小写」的勾选也一并生效。

## 已下载内容

`/downloaded` 是下载完成之后的操作台：列出**本服务下载过并留有存档的作品**，可勾选后批量处理。它和「活动 → 历史」看的是同一批任务行，但问的不是同一个问题——历史按任务排列、回答「这次跑得怎么样」，这里按作品排列、回答「这本书现在在哪、要不要再动它」。

| 分区 | 含义 |
|------|------|
| 全部 | 所有下载完成且存档还在的作品 |
| 待打包 | 有存档但从未打过包 |
| 已打包 | 已经产出 CBZ（判据是产物文件，不是任务状态） |
| 需干预 | 打包停在缺分卷、缺密码或归档路径不可用上，补齐后重新打包即可 |
| 打包失败 | 打包报错，行内附失败原因 |

- **封面网格与列表两种视图**，切换、搜索、排序、分页全部写在 URL 里，可以直接收藏。
- **详情页的返回键回到你来的那一页**：从这里点进作品详情，返回键就写「返回已下载」并带着你原来的分区、筛选、排序和页码；从「待审核」进来则写「返回候选列表」。直接输网址或从书签打开时回落到候选列表。
- **在详情页做操作不会改掉返回键**：拉取元数据、重新打包这些动作做完，返回键仍然写「返回已下载」，也仍然带着你原来的筛选与排序。（此前每次操作后它都会退回「返回候选列表」，把人丢进一个并不包含这本书的列表。）
- **勾选后浮出批量工具条**，三个批量动作：
  - **批量打包 / 重新打包** —— 一次点击，不额外确认。已打包的作品会重排同一个打包任务，**成品覆盖原文件**，不会在旁边多出 `book (2).cbz`。
  - **批量重新下载** —— 按原来源重抓，完成后覆盖现有文件；复用原任务行并累加尝试次数。要二次确认。
  - **移除** —— 分成两个按钮：「移除记录」只删下载与打包记录，磁盘上的文件全部保留；「移除并删除文件」才会连 CBZ 与原始压缩包一起删。**默认不动文件**，这是两个独立的确认对话框而不是一个复选框，因为只有能看清按了哪个，「默认不删」才有意义。两者都保留候选与元数据，因此随时可以重新下载。
- **改归档路径**（单件）：在作品详情页直接设定库内目录与文件名。目录不存在**自动创建**（而且先过完所有校验再建，反复试错不会在书库里留下空目录）；目标名称已被其他作品占用则**直接拒绝**，不会默默加一个 ` (2)` 了事。保存后自动重命名并移动已有的 CBZ，之后**重新打包会落回你选的位置**，不会被归档路径模板搬回去。`..`、绝对路径与不能用于路径的字符一律拒绝，并指明是哪一段的哪个字符。
- **详情页的归档路径框已经预填好**：打开作品详情页时，目录与文件名两栏不会空着——**已归档成功**的填它现在记录在案、磁盘上真正所在的路径；**归档失败或还没归档**的按**当前**路径规则（默认模板，以及命中的「按规则匹配的模板」）现算一个填进去，省得你对着空框猜它会被放到哪。你手动指定过路径的作品是例外，表单照旧显示你填的那个：打包最终用的就是它，改填模板的答案反而是在骗人。
- **批量打包按最新模板重算路径**：每次批量打包前，会先用当前的归档路径模板为每个作品重算一次目录与文件名，再逐件打包。你在详情页手填过路径的作品不受影响——模板是默认值，默认值不推翻你的决定。若渲染出的路径不合法（过长、含特殊字符），**这本书就不动**：既不改路径也不打包，而是进入「需干预」分组并写明原因，方便你改标题或手填一个路径后重排。
- **有任务在跑的作品不能移除或重新下载**：下载或打包工作器正持有那一行，页面会说明原因。先取消，再动。
- **打包不看候选状态、只看有没有存档**：一个候选只有一个状态字段，由它派生的所有任务共用，任何任务被领取都会把它置为「处理中」。所以「预览图源已下完、种子还在跑」这种再普通不过的情况，以前会让「打包」拒绝一本明明已经就绪的书。现在只有**驳回**与**尚未定夺**（待审核 / 待补充信息 / 待修订）会拒绝打包——那是关于「要不要入库」的判断，理应由状态回答；「有没有东西可打包」则由产物本身回答。
- **打包前一定先补元数据，批量与单件一视同仁**：归档路径、文件名和整个 `ComicInfo.xml` 都是从元数据推出来的，而成品路径随后会写进产物记录。因此只要候选带 eh 链接而元数据还缺，打包会**先刮一次再动手**；否则书会以 `candidate-57.cbz` 落库，事后补刮也搬不回来。刮取失败不会卡住下载：仍按已有标题打包，并记一条日志。
  批量打包过去漏了这一步，而且后果比单件更重：批量会**先算好路径并钉住**，而钉住的路径优先于模板——所以一本在元数据还没刮到时批量打包的书，错名字会被当成「你自己定的」记下来，之后再怎么重新打包都不会自己纠正。现在批量在为每件作品算路径之前先补元数据。你手填过路径的作品仍然不刮：那条路径不从元数据推出来，刮了也用不上。
- **移除会留一条审计记录**（含「是否连文件一起删了」）。终态任务行本来被当作永久记录，直接删会让历史对自己的完整性说谎。
- **操作就地更新，不再整页刷新**：点「打包」「重新打包」这类按钮时，只有内容区被换掉，侧边栏与顶栏不重新加载，**页面也不会跳回顶部**——在一屋子书里点第四十本，视线还留在第四十本上。提示信息、行内状态和批量工具条都照常出现。
  被拒绝的操作同样就地显示原因（比如归档路径不合法），不会出现「按了按钮却像什么都没发生」。
  确认对话框跟着它确认的那个动作一起消失：点「确认」后弹窗随内容区更新关闭，不会盖在新内容上，也不需要再点一次「取消」。就地更新过的页面里，之后每一次需要确认的操作同样留在原地。
  关掉 JavaScript 也照旧可用：每个动作本来就是真表单，会正常跳转并回到完整页面。
- **上一个 / 下一个作品**：详情页主操作条按候选 id 排的快捷翻页，看完一本接着看相邻的一本，不用退回列表再找。
- **手动补画廊链接（切换 Eh 编号）**：ingestor 漏抓或挂错时，可以手填一本换掉。只接受完整的画廊 URL，裸数字 gid 会被拒绝（400）。
- **手动补种子 / 预览页**：粘贴 magnet 链接（校验 `xt=urn:btih:` 后的 32–40 位十六进制 infohash）即手动把种子喂回 EH 下载链路；粘贴 telegra.ph / graph.org 预览页链接可补齐已有的预览、留空则清除它。两者都是 ingestor 漏掉时的逃生门。
- **编辑已打包作品的元数据会顺手重新打包**：改了会写进 `ComicInfo.xml` 或文件名的字段（标题、艺人等）保存后，自动排一个 CBZ 重打包任务，让书库与元数据保持一致，不用记得再去点一次「重新打包」。
- 页面只在确实有东西在打包时才轮询；一屋子打包完的书不会让进程每两秒醒一次。**批量打包排队后进度会自己开始更新**，不需要手动刷新一次。

跨作品的命名规则请用「设置 → 路径」里的归档路径模板（`{category}/{artist}/{title}`），这一页的改名是给单本书做例外用的。**这里不提供**阅读器、书架分组，也不会扫描不是本服务下载的文件。

## 标签翻译

服务启动时会从 EhTagTranslation 的 GitHub Release 下载 `db.text.json.gz`，缓存到 `data/ehtag_db.json`，并在内存中建立 `namespace:tag` 索引，用于把 ExHentai 官方 API 返回的英文元数据翻译成中文。

- 每次启动先用 `ETag` 做条件请求，未变更则直接使用本地缓存；距上次检查不足 24 小时时完全跳过网络请求。
- 网络不可用时自动降级到本地缓存；没有缓存时跳过翻译，元数据保留英文原文。
- 中文值写入 `Title`、`Artist`、`Group` 等主字段，英文原文保存在对应的 `*Raw` 字段，审核页可展开查看。
- 如需关闭该功能（例如离线部署），在 `.env` 中设置 `TAG_TRANSLATION_ENABLED=false`。

## 下载队列

审核通过的候选会进入下载队列，「活动 → 队列」页展示待处理、进行中、已暂停和失败的任务（失败任务不会消失，以便重试）。

- **重试**：复用同一任务行，不会产生重复作业，尝试次数会累加；候选会从失败状态回到已通过。因永久原因失败的任务（例如文件超过 Bot API 上限）不提供重试按钮。
- **暂停 / 继续**：只对尚未开始的任务生效。暂停后工作器不会领取它，点击继续即重新排队。已在下载中的任务无法中途挂起，只能取消。
- **取消**：任务终止，候选退回「待审核」队列，不会丢失。已完成的任务不可取消。取消停放中的种子任务会同时从 qBittorrent 移除该种（不删文件）。
- **等待种子**：`WAITING_TORRENT` 行额外展示进度百分比、做种者数、速度、ETA 与停滞时长，并提供切换来源的动作，详见下文。

**Telegram 单文件 20 MB 上限**：Telegram Bot API 拒绝下载超过 20 MB 的文件（`getFile` 返回 `file is too big`）。这是官方接口限制，与代理、超时或重试无关。上限属于**协议**而不是 Token，所以登录一个普通用户账户（MTProto）即可绕过：见下文「Telegram 用户账户」。未登录用户账户时，超限附件不会交给 Telegram 源，而是按下节的降级链路选路。

## 下载来源与降级链路

审核通过时按「画质优先、成本其次」自动选路，元数据始终以 ExHentai 画廊为唯一权威源：

| 顺序 | 来源 | 画质 | 触发条件 |
|------|------|------|----------|
| 1 | `TELEGRAM` | 原档 | 有压缩附件且不超过 20 MB |
| 2 | `TELEGRAM_USER` | 原档，且免费 | 有压缩附件（不限大小）且已登录 Telegram 用户账户 |
| 3 | `EH_TORRENT` | 原档，且免费 | gdata 报告有种子且已登记 qBittorrent |
| 4 | `TELEGRAPH` | 1280px 重编码，约为原档 5%–10% | 消息带 `telegra.ph` / `graph.org` 预览页链接 |

- **超限本子首选用户账户**：那是上传者发的同一个文件，不用等做种者、不消耗 GP，也不会因为无人做种而停滞。未登录时该位次自动跳过，选路退回种子。
- **小文件仍走 Bot**：即使登录了用户账户也不接管 20 MB 以内的附件——Bot 本来就在收消息，不需要额外凭据。
- **种子是没有用户账户时超限本子的原档来源**：内容是上传者的原始压缩包，不消耗 GP，也不受 20 MB 限制。
- **ExHentai Archive Download 不参与自动选路**：它消耗 GP，属于操作者决策，只在审核详情页提供「用 Archive Download 取原档」按钮。四条来源都不可用时，审核会直接报「没有可用的下载来源」而不静默花 GP。
- **预览页是兜底，不是默认**。页数完整（实测 22/22、15/15、78/78）且免 Cookie，但成品是统一缩到宽 1280 的重编码版本，只作阅读级替代。
- 预览页链接通常是超链接，URL 只存在于消息的 `text_link` entity 里；只带预览链接的消息也会被纳入候选。
- 抓到的张数与画廊 `filecount` 不一致时**不发布残本**：任务以 `TELEGRAPH_PAGE_COUNT_MISMATCH` 失败，候选退回「需要补充信息」并显示「预览页只有 N/M 页」，补齐链接后重试复用同一任务。设 `TELEGRAPH_REQUIRE_FILECOUNT_MATCH=false` 可关闭该门禁。
- 预览页图片来自频道自建的第三方图床，因此抓取前后有独立门禁：仅 https、DNS 解析后拒绝回环与内网、重定向逐跳复检（上限 3 跳）、单图与单本字节和张数上限、图片魔数校验（拒绝 SVG 与 HTML），且使用不携带任何 Cookie 的独立 HTTP 客户端。防盗链 403 时会带 `Referer: https://telegra.ph/` 重试一次。
- 来源等级写入 `ComicInfo.xml` 的 `<ScanInformation>`（形如 `TELEGRAPH_PREVIEW w1280 15p 7.5MiB`、`EH_TORRENT original 121.0MiB`）与任务详情，**不改文件名**，便于日后用原档替换而不破坏书库索引。

## Telegram 用户账户（大文件下载）

Bot API 的 20 MB 下载上限在协议里，换 Token 或加代理都没用；同一个文件用普通用户账户走 MTProto 就没有这个限制（上限 2 GB，Telegram Premium 4 GB）。**Bot 仍然是收消息的那一端**，用户账户只负责把超限附件取回来，两者并存。

在「设置 → 外部连接 → Telegram 用户账户」登录：

1. 在 [my.telegram.org](https://my.telegram.org) 的 *API development tools* 创建应用，拿到 **API ID** 与 **API Hash**（属于你自己的账户，本项目不内置共享的一对）。
2. 填入 API ID、API Hash 与带国际区号的手机号，提交后 Telegram 会向该账户发送验证码。
3. 输入验证码。若账户开启了两步验证，页面会接着要求输入两步验证密码——此时验证码不需要重新获取。

- **凭据存储**：API 对与会话串分开保存在 `data/private/`（`telegram_user_api`、`telegram_user_session`），页面与 JSON 都不回显，日志也不记录。会话串等同于账户完整凭据，请与 `data/private/` 一并按机密备份。
- **断开**：会同时删除会话串与 API 对；超限附件随即回退到种子或预览页来源，已下载的文件不受影响。
- **失效**：在 Telegram 客户端的设备列表里注销该会话后，本页显示「连接异常」并说明需要重新登录；受影响的任务以 `TELEGRAM_USER_UNAUTHORIZED` 失败，重新登录后点重试即可复用同一任务行。
- **按消息定位而非 `file_id`**：MTProto 的文件引用是按账户的，Bot 给出的 `file_id` 在用户账户下无法解析，所以下载任务记录的是 `(chat_id, message_id)`，运行时重新读取那条消息。因此**上传者删除原消息后无法再用此来源**（报 `TELEGRAM_USER_MESSAGE_GONE`，不重试）；同理，登录的账户必须在该频道里。
- 升级前入库的旧候选也可用：附件里没有内联的消息坐标时，会从 `source_messages` 回查，无需重新收一遍消息。
- **手动取原档**：作品详情页的来源栏新增「Telegram 大文件」按钮（`POST /candidates/{id}/telegram-user`）。未登录时该按钮显示为不可用并说明原因，而不是隐藏。

## EH 种子与 qBittorrent

种子下载全程交给外部 qBittorrent，**主进程不跑 P2P、不引入 libtorrent**，低配目标不受影响。在「设置 → 归档」页登记地址、凭据、分类与两个保存目录后即可使用，凭据加密保存在 `data/private/` 且页面不回显。

- **选种**：gdata 响应里已经带 `torrentcount` 与 `torrents`，发现种子不需额外请求。多条时排除 `resample` 重采样版，再取 `fsize` 最接近画廊 `filesize` 者，最后取最新。
- **取 .torrent**：`torrents[].hash` 只是 infohash，文件需要登录态从 `gallerytorrents.php` 取，链接一律从页面解析而不硬编码。本地用 bencode 算 infohash 与 gdata 比对，不一致直接 `TORRENT_FILE_INVALID`，不推给客户端。
- **.torrent 属于凭据**：它的 announce 内含账号 passkey，只停留在工作目录，不进书库、不入日志、不入审计。也不用裸磁力链替代：EH tracker 需要 passkey。
- **推种**：走 `torrents/add`，显式下发 `savepath` 与 `category` 并关掉 `autoTMM`（否则分类规则会覆盖保存路径，EhBot 会去错目录找文件），不传 `root_folder` 以保留种子结构。不用监视文件夹，不碰客户端配置。
- **兼容新旧 WebAPI**：登录成功在部分构建与反代下是 `204` 而非 `200 Ok.`，加种在 WebAPI 2.11+ 返回 JSON 报告而非 `Ok.`，两者均按成功处理；仅当报告里无任何成功且 `failure_count > 0` 时判 `TORRENT_PUSH_REJECTED`。
- **重复加种不是错误，但会提示**：客户端已持有该 infohash 时（新版回 `409`）任务照常停放，页面标注「该种子已存在于 qBittorrent」——因为实际干活的是别人创建的条目，其保存目录与分类未必是刚下发的那些，收货可能找错目录。
- **存活与重启**：推种成功后任务进 `WAITING_TORRENT`，不占用下载并发名额，由独立轮询任务每 `TORRENT_POLL_SECONDS` 秒拉一次进度。停放任务每轮从数据库读取，因此重启后自动按 hash 重新挂上；客户端里已无该 hash 则置 `TORRENT_VANISHED`（可重试）。
- **卡种不是错误**：`stalledDL` / `metaDL` 且做种者为 0 时，任务继续等待并在「活动 → 队列」页显示「无做种者，已停滞 N 分钟」，**不自动失败、也不自动降级**。降到预览级或花 GP 都是操作者决策，页面提供「改用预览图源」「用 Archive Download」「取消」三个动作，切源与取消会从客户端移除该种。
- **做种可见且可停**：完成后仍在做种的任务继续留在「活动 → 队列」页（其他源完成即消失），显示上传速率并提供「停止做种」；停止只从客户端移除条目，不删已归档文件。因为做种仍在占用带宽与磁盘，它就不应该从页面上消失。
- **页面自动刷新**：进度由后台轮询写入，因此存在下载中或做种中的任务时，「活动 → 队列」页每 `TORRENT_POLL_SECONDS` 秒自刷；队列空闲时不刷。轮询每轮输出 `torrent_progress` 日志（状态、百分比、做种者、速率），便于不开页面也能跟进度。
- **收货硬链接优先，其次复制，绞不移动**：移动会破坏做种。默认 `TORRENT_KEEP_SEEDING=true`，完成后继续做种；关掉时也只从客户端移除条目，不删文件。单文件压缩包直接登记为 artifact，目录则校验为图片后按 `ZIP_STORED` 打包，之后完全复用现有归档流水线与安全门禁。
- **下载后自动打包（默认关闭）**：开启后收货完成即自动入队归档流水线，无需手动点「打包」。默认关闭是因为打包意味着发布到书库，不应成为下载完成的副作用。**开启时必须填写「保存目录（EhBot 视角）」**，且保存时会验证该目录可列出（仅 `is_dir()` 不够：无读权限的挂载也能通过），否则无人看着的打包会在几小时后才失败。打包失败不会把下载标成失败：artifact 已登记，仍可手动转换，日志记 `TORRENT_AUTO_PACK_FAILED`。
- **两个保存目录**：`保存目录（客户端视角）` 随加种请求下发，`保存目录（EhBot 视角）` 用于读取。客户端在其他容器或 NAS 时两边路径不同，因此分开登记；保存时就校验后者可读，而不是等三个小时后才发现写错。
- 置空客户端地址或设 `TORRENT_ENABLED=false` 即跳过这一级，选路直接降到预览页。

## 归档处理

下载完成后的压缩包经一条固定流水线发布为 CBZ：分卷检查 -> 密码尝试 -> 安全校验 -> 解压或流式复制 -> 同一后端打包 -> 原子发布。

- ZIP/CBZ 使用内置 `zipfile-default` profile，成员直接流式写入 CBZ，不需要先全量解压；图片以 `ZIP_STORED` 写入，不重复压缩。
- RAR、7Z、分卷包和 `zipfile` 无法打开的加密 ZIP 使用 `7zz-default` profile，通过受控子进程调用；主进程不加载第三方 DLL。
- 7-Zip 不依赖发行版包：服务首次启动时从 `ip7z/7zip` 官方 GitHub Release 拉取固定版本的 `.tar.xz`，校验 SHA-256 后解包到 `data/tools/7zip/<版本>/`，优先使用静态链接的 `7zzs`，因此 slim 镜像无需额外运行库。存档只用 Python 内建 `tarfile` 解开，不存在「解压工具需要解压工具」的自举问题。
- 安装目录按版号隔离且幂等：已有可用二进制时直接复用，校验失败的下载会被丢弃且不影响现有安装。设置 `ARCHIVE_TOOLCHAIN_AUTO_INSTALL=false` 可关闭自动拉取（离线部署），此时可用「设置 → 归档」页的下载按钮、预先运行 `python -m scripts.install_seven_zip --data-path /app/data`，或直接填写宿主自带的 `7zz`/`7z` 路径（PATH 和 Windows 默认安装目录作为回退）。
- 官方未发布二进制的平台（例如 Windows 开发机）不会尝试下载，页面会说明需要手动填写路径；归档功能在 Linux/Docker 上不受影响。
- 全量解压前先校验路径穿越、绝对路径、符号链接、嵌套压缩包、成员数、解压大小、异常压缩率、目录层级和图片魔数，任何超限直接失败。
- **文件头与后缀不一致时按文件头修正，不再让整本失败**：上游用批量转换工具留下的 `.png` 里装着 JPEG 是常见情况，以前一页不符就导致整个压缩包报 `ARCHIVE_MEMBER_FAKE_IMAGE`、两百页一起打不出来。现在只要文件头能被确认是图片（JPEG / PNG / GIF / BMP / WebP），这一页就按**真实格式**的后缀发布。CBZ 里的页名一律由本服务重新生成、从不沿用包内原名，所以这是一次改名而不是转码——为了迁就一个谁都看不到的文件名去重编码只会白掉画质。反过来，**文件头压根不是可识别图片时依旧整包拒绝**（例如 `page.jpg` 里装着可执行文件），魔数门禁没有被放宽。
- **没有后缀但文件头是图片的成员也算页**：有些上传者把页命名成 `001`、`002`，以前这种包会以「不包含可发布的图片页」失败——明明整包都是图。
- 分卷不完整时任务进入「待补分卷」，密码全部尝试失败时进入「待补密码」；补齐后重新入队会复用同一任务，不会产生重复作业。
- 密码库条目加密保存，页面不回显密码，日志和审计也不记录密码本身；主密钥保存在 `data/private/archive_password_key`。
- 在「设置 → 归档」页面可调整安全限制、是否保留原始压缩包、工具 profile 的可执行文件/超时/启用状态和密码库条目（密码库自己另有一页）。页面只能选择已登记的 profile，不接受任意命令行。
- 书库目录和工作目录在「设置 → 路径」页修改，必须是绝对路径且可写（不存在时自动创建），保存后下一个任务即生效，无需重启；清空输入框即恢复环境变量默认值。同一页还可编辑归档路径模板并即时预览成品路径，并选择 `{title}` 取日文还是英文标题（默认日文：英文标题常带 `:`、`/` 这类不能用于路径的字符，模板会因此判为名称不合法）。要固定某一种语言可直接写 `{japanese_title}` 或 `{english_title}`；缺失时回落到另一种，两者都没有才用画廊 ID。数据目录存放设置数据库本身，只能通过 `DATA_PATH` 环境变量指定。

该页最上方的「归档路径来源」可在**模板与规则**与 **AI 生成**之间二选一（详见上一节）；两者互斥，
AI 模式下模板与规则不生效。该页还有「按规则匹配的路径模板」：运营者可维护一组 `{类 SQL 条件 → 路径模板}` 规则（条件与自动审批共用同一 DSL 与逐条大小写开关，模板合法性与默认模板同一道校验门）。打包某部作品时，取优先级最高且条件命中其元数据的第一条规则模板；全部不命中则回落上方默认模板。作品详情页手动指定过归档路径的（`is_manual`）始终优先于规则与模板。保存前可用「试跑」预览这条条件会命中哪些历史候选（试跑只读、不落任何记录）。

### 路径来源与 AI 路径（`/settings/paths`）

「设置 → 路径」页最上方新增**归档路径来源**，二选一：

- **模板与规则（现状，默认）**：路径由默认模板、按规则匹配的模板和作品详情页手动指定的路径决定，
  与以前完全一致。
- **AI 生成**：由当前生效的模型链读取作品元数据，输出**目录 + 文件名**两段（`.cbz` 由本服务追加）。
  此时下方的模板与规则**不生效**（页面会置灰并说明），默认模板改称「兜底模板」。

用哪条模型链由同页下方的「**路径决策模型**」决定：默认**跟随全局默认**——即「设置 → AI 供应商」页
顶部那张主力 + 备用列表；也可以选「本页单独指定」，为路径决策单独维护一张列表（例如用一个更便宜 /
更快的模型专门起名），两张列表互不影响。

AI 模式下：

- **答案会被缓存，而且缓存是语义的一部分。** 指纹覆盖「送进模型的元数据 + prompt 全文 + 模型链
  （含各供应商的基础地址与逐模型请求参数）」，**API Key 不进指纹**——轮询换一把 Key 不会让全库路径
  失效。指纹相同就直接用缓存，**不发起任何请求**；改 prompt、换模型链或参数、或元数据变了才需要重新
  询问。作品详情页预填、已下载列表、重新归档的计划阶段**都只读缓存**，打开一次页面不会向第三方发出
  任何东西。
- **第一次生成发生在打包时**：把「归档路径来源」切成 AI 后，下一本打包的作品会向模型询问并把答案
  记下来；它只写 `artifacts.library_relative_path`（和以前一样），不会写入人工 pin。
- **模型链全部失败**（网络错误、鉴权失败、超时、返回的不是合法 JSON/路径都算失败）时默认**进「需
  干预」**：打包任务停在「待定归档路径」，错误码 `AI_PATH_UNAVAILABLE`，消息写明每个模型失败的原因。
  勾选「AI 不可用时回退到规则匹配」后改为回落到「兜底模板」入库并记一条 `ai_path_fallback`。
- **模型的回答不是可信输入**：非法字符、Windows 保留名、超长段交给 `safe_library_name` 清洗并记
  `ai_path_sanitized`；只有 `..`、绝对路径或盘符、清洗后文件名为空、整条路径超长才判失败。安全靠的是
  代码校验，不是 prompt 的措辞。
- **界面标注来源**：由 AI 生成的路径在作品详情页「归档」面板与已下载列表带 `AI 生成` 徽标（判定是
  「缓存里那条路径 == 当前记录在案的路径」，所以人工改名后徽标自动消失）。
- **清除缓存**按钮丢弃全部已缓存的答案（例如换了 prompt 想立刻重来），下一次打包会重新询问模型。
  页面上还显示当前模型链与缓存条数。
- **结果面板**分「入队打包 / 入队重算路径 / 移动文件 / 位置未变 / 跳过」五类，计数与下面的明细来自
  同一份数据；入队的作品由打包队列在后台处理，页面收到 `EVENT_CONVERSION` 后自动刷新。
- **整库重排（一键重新归档）**：AI 模式下同页的「一键重新归档」按缓存执行，**计划阶段绝不向模型发
  请求**。默认范围是三类作品：「尚未成功归档」（入队打包）、「没有当前答案」（缓存缺失，或 prompt /
  模型链 / 元数据变了——入队重算路径）、「答案已是当前、只是记录路径与它不符」（当场移动文件，不调
  模型）。已经按当前 prompt 定好路径的作品默认**不纳入**，可用「默认重排时也重算」开关把它改成重新
  询问（即「让 AI 再给同一本书起个名字」）。
- **已打包的作品只移动，不重新打包**：「重算路径」的任务只向模型问一个新答案，再把已有的 CBZ 移到
  新位置并改写记录，内容与 ComicInfo 都不变——重新压缩既费宿主机 CPU 又不会改变任何字节。尚未打包
  的作品照常入队打包，打包时询问模型。
- **强制 = 全库重新询问**：跳过上面的所有「不纳入」与跳过规则，缓存已是当前答案的作品也重新询问，
  手动指定的路径被覆盖（覆盖后 `is_manual` 归零，所以之后再改 prompt 仍可重排）。每件已归档作品都会
  产生一次模型调用（还要乘上备用模型的重试），可能耗时较长并产生费用。
- **试跑**：只计划与报告——不移动文件、不入队、不写 pin、也不调用模型；结果面板与真实运行同形，只是
  标题写作「试跑结果」。强制的代价提示就落在这里，建议先试跑再执行。
- **执行方式与三个开关**：`每批处理数量` 决定一次准备多少件作品（一次运行仍覆盖全部范围内作品，分批
  只是避免一次性把整库读进内存）；`并发数` 决定同一批内同时拉取多少件作品的元数据（模型调用发生在
  打包队列里，始终逐件进行，复用既有超时与失败上报）；`使用流式输出` 让模型请求走 SSE，只改变传输
  方式、结果完全相同，默认关闭（部分自建端点只支持非流式）。

**提示词（prompt）**：默认给出上面那份参考提示词（按「刊发形式 / 社团 / 作者 / 系列名 / 作品名」
固定五级、缺层省略、社团与作者各只有恰有 1 个时才成层、杂志取「刊名 + 年月」、作品名保留完整原题）。
可以直接改写；用 `{{metadata}}` 占位符把元数据 JSON 就地插入，不写则作为用户消息追加。「恢复默认
提示词」回到参考文本。**prompt 全文参与指纹**，所以改一次 prompt 全库都需要新答案。

**关于数据外发**：AI 模式下作品的元数据（日文标题、社团、作者、标签等）会发送到你在这一页配置的
端点。这是显式选择（默认关闭、不配置就没有外发）；使用本地 / 自托管的 OpenAI 兼容服务
（Ollama、LM Studio 等）则元数据不离开宿主机。API Key 与归档密码同一套主密钥加密存储，页面不回显、
日志不记录。

### AI 供应商（`/settings/ai`）

这一页管理「用 AI 决定归档路径」所需的模型服务，结构照 AstrBot 分两层：**供应商**（一个端点 + 凭据）
与**模型**（挂在供应商下的一条可用模型名）。页面是「左列供应商、右列该供应商的配置 / Key / 模型」的
工作台，顶部与底部各有一块全局区域：

- **全局默认模型**（页面顶部）：一张可跨供应商的有序链，**第 0 位是主力**，其余是备用回退。
  打包以及所有「没有单独指定模型」的地方默认就用这张列表。旁边的「测试全部模型」一次跑完链上每一条。
- **新增供应商**：名称、供应商编码（目前只有「OpenAI 兼容」）、基础 API 地址（填到版本段为止，
  例如 `https://api.openai.com/v1`，本服务自行追加 `/chat/completions`；本地服务同理，
  如 `http://ollama:11434/v1`）、超时（5–300 秒）、重试次数（0–3）、**自定义请求头**（JSON）与
  **供应商级默认请求参数**（JSON）。地址必须是带主机的 `http://` 或 `https://`，保存时即校验。
  自定义请求头给需要额外头的网关用；密钥请加到 Key 列表（加密存储），不要写在头里。
  **MiniMax** 填 `https://api.minimax.chat/v1`（国际版 `https://api.minimaxi.com/v1`），Key 用控制台
  里那串以 `eyJ…` 开头的 API Key，**不是 GroupId**；它的 1004「login fail: Please carry the API
  secret key in the 'Authorization' field…」对「没带 Key」和「Key 不对」是同一条，所以看到它先核对
  Key 本身（以及 CN/国际版有没有混用），而不是怀疑本服务没发请求头。MiniMax 的原生接口把错误放在
  HTTP 200 的 `base_resp` 里，本服务同样能识别并给出与 401 一样的「换一把 Key」语义。
- **供应商工作台**：左列点选一个供应商，右列可以：

  1. **批量添加 API Key**：一个文本域一次粘贴多把，每行 `备注:key` 或裸 key（`#` 开头与空行跳过）。
     每个供应商可存多把，请求在它们之间**轮询**；遇到 401/403（Key 被拒）或 429（限流/额度）的那把会
     被**冷却 10 分钟**并自动换下一把，冷却状态落库，重启后不会立刻又撞同一把。列表只显示备注、状态
     与时间，可单独「取消冷却」。Key 与归档密码同一套主密钥加密存储，**永不回显原文**，日志也不记录。
  2. **添加模型**：手填模型名（逗号或换行分隔）一次加多个，或点「从 /v1/models 拉取」把供应商返回的
     名称列成勾选清单后批量加入；已存在的名字自动去重，清单里可直接**批量启用 / 停用**。
  3. **逐模型参数**：每个模型可展开填一段 JSON（`temperature`、`max_tokens` 或任何额外字段），
     覆盖供应商默认值。**留空就是不发**——请求体默认只有 `model` 与 `messages`，这是让推理模型
     （拒绝 `temperature`、只认 `max_completion_tokens`）与严格网关也能接入的关键。
  4. **测试**：对某个模型（或整条链）发一次**最小的真实对话请求**并要求回一段 JSON。失败原因与时间
     会显示出来，但**测试不是保存门槛**——未验证、已停用、甚至供应商当前没有可用 Key 的模型都能进链，
     能不能用交给「测试」按钮回答，而不是等一本书打包到一半才发现。
  5. **编辑 / 删除供应商**。删除会一并移除它的 Key、模型以及它们占据的模型链位置。

  模型链用「设为主力 / 加入备用 / 上移 / 下移 / 移出」调整顺序（界面里看到的顺序就是能保存的顺序）；
  每一项都是「供应商 + 模型」，主力与备用可以来自不同供应商。打包时按顺序尝试，某一条失败自动回落下一条。

**关于数据外发**：启用 AI 模式后，作品的元数据（标题、社团、作者、标签等）会发送到你在这一页
配置的端点。这是显式选择：不配置供应商、不开启 AI 模式就没有任何外发；使用本地 / 自托管的
OpenAI 兼容服务（Ollama、LM Studio 等）元数据不离开宿主机。

## 封面缩略图

审核列表的封面不直连图床，而是由本机代理后再交给浏览器：URL 形如 `/api/v1/thumbnails/<hash>`，`hash` 是「来源 URL + 变体」的 SHA-256。

- **不回传上游地址**：让 `<img>` 指向 ExHentai 的 CDN 等于把本部署渲染过的每一张封面都告诉那台主机，而且它一拒绝防盗链页面就全线破图。
- **不是开放代理**：接口只接受 hash，不接受任何调用方给的 URL。抓取画廊元数据时才会在同一个事务里写入 `candidates.thumb_url` 和一条 `PENDING` 的 `thumbnails` 记录——这条记录是唯一的准入口，没有它的 hash 一律不抓。
- **可以永久缓存**：hash 覆盖了来源身份，同一 URL 换不出别的图，因此响应带 `ETag` 与 `Cache-Control: immutable`，二次请求靠 `If-None-Match` 换 `304`。
- **出站字节全部由自己产出**：抓到的图先过魔数与像素上限，再由 Pillow 解码并统一重编码为 WebP（长边上限 512，只缩不放）。上游用 `200` 送回 HTML 错误页的情况会被魔数门禁挡住，不会存成封面。
- **抓取受控**：与预览页共用同一套 SSRF 门禁（仅 https、解析后拒绝回环与内网），同一 hash 的并发请求合并为一次抓取，全局出站并发上限 4，防盗链 403/404 时带 `Referer: https://exhentai.org/` 重试一次。
- **失败返回占位图而不是 404**：`<img>` 的 404 会渲染成破图图标且无法用样式补救，因此失败时返回一张真实的占位图并配 `X-Thumbnail-State: failed` 头与短缓存。
- 设 `THUMBNAILS_ENABLED=false` 即完全关闭该服务，列表渲染占位图，不向图床发出任何请求。

## 首次登录

服务首次启动时会生成一个一次性的管理员密码，并直接打印到控制台：

```
docker compose logs
```

- 用户名固定为 `admin`，密码以横幅形式打印在启动日志顶部，不需要去翻数据目录。
- 同时会写入 `data/bootstrap_admin_password` 作为备份（仅当前用户可读）。

Windows 上无法验证托管的 7-Zip 安装（官方只为 Linux/macOS 发布该形式的二进制），这部分用 Docker 验证（需已启动的 Docker 引擎）：

## 日志

服务输出结构化 JSON，一条记录一行。关键设计：

- **一个格式覆盖所有输出路径**。Uvicorn 的访问日志与启动日志都被收编走 JSON 管道，同时获得同样的脱敏。你看到的所有日志都是同一个格式，任何 `· jq` 或集成上去都不需分流。
- **异常堆栈进日志**。`logging.exception(...)` 现在产生 `exception` 字段，与 `event` 一样走脱敏。四个防御性 worker 循环（下载 / 打包 / 种子转发 / 应用启动）报错时不再只剩一个事件名。
- **脱敏覆盖消息 / 异常 / 栈三个字段**。Telegram bot token、Authorization、Cookie、URL query 与 `ipb_pass_hash` 等都不会出现在任何输出上，包括访问日志。
- **每个请求一个关联 id**。在 `X-Request-ID` 响应头里返回相同的 id，也写入该请求期间的所有日志行。查一次错误只需在页面处拿到那个 id、然后在日志里筛。

### 运行日志页面（`/logs`）

实时查看本进程的日志，不必为看一行报错去宿主机敲 `docker compose logs`。

- **实时推送，不是定时刷新**。页面订阅 `/api/v1/logs/stream`（SSE），记录写出的同一刻到达。连接断了浏览器自己重连，重连时补发最近 50 条，因此断线期间的记录不会缺口。
- **级别是下限，不是等值筛选**。选「警告」仍然显示错误——一个会把错误藏起来的「警告」筛选，等于在最需要证据的时候丢证据。默认「信息」；可选「调试 / 信息 / 警告 / 错误」。
- **页面的筛选与运行级别是两回事**。筛选只决定显示哪些行；当前进程实际把哪一级写进日志，由「系统」页的「日志等级」决定——保存即重建进程级门槛、无需重启，切到「调试」同时打开 uvicorn 访问日志。这一项在第一次启动前不存在，所以「页面起来之前」的启动失败只能靠环境变量 `LOG_LEVEL` 排查；页面会标出当前进程级别是哪一个。
- **内存缓冲 + 文件兜底**。最新 1000 条留在内存里，所以 `LOG_TO_FILE=false` 或数据目录只读时页面照样有内容——那恰好是最需要看日志的部署。进程刚启动、内存里还没有该级别的记录时，改读 `<data>/logs/` 下的日志文件，页面会说明这一次读的是磁盘。
- **暂停**用于按住一屏正在滚过去的内容；暂停期间的记录攒着（上限同页面条数），继续后补上。
- **没有清空、没有下载按钮**。缓冲区是排查现场的证据，一个会删掉它的按钮与这个页面的目的正好相反；日志文件本来就在运行容器的人手里，从页面导出只会多一个可被影响的路径。
- **脱敏与其他输出路径完全一致**：缓冲里存的就是 `JsonFormatter` 产出的那一行，凭据不会因为多了一个页面而多一条泄露路径。
- **关掉 JavaScript 也能用**：首屏由服务端渲染，级别下拉是一个普通 GET 表单，只是不再实时。

环境变量（都在 `.env.example` 里有默认值）：

| 变量 | 默认 | 作用 |
|------|------|------|
| `LOG_LEVEL` | `INFO` | 进程**首次启动**的默认级别。启动后改由「系统」页的「日志等级」接管（见「系统设置」），`LOG_LEVEL` 只在库里还没有这一项时决定级别，也是唯一能在页面起来之前生效的方式 |
| `LOG_TO_FILE` | `true` | `false` 只走 stdout，不写文件 |
| `LOG_FILE_BACKUPS` | `5` | 保留最近的多少个 UTC 日（每日一个文件 + 每日一个 `_error` 文件，按日清理） |

文件输出按 UTC 日切割，落在 `<data>/logs/{yyyy-MM-dd}.log`（错误另有一份 `{yyyy-MM-dd}_error.log`），位于已是绑定卷的数据目录下，随容器重建保留；早期版本的单一文件 `<data>/logs/ehbot.log` 仍被读取作为兜底，但不再写入。Docker 端由 `compose.yaml` 里的 `logging:` 块限制 stdout（10 MB × 3 份），与容器内按日轮转独立：只作一个都会在另一条路上填满磁盘。

以下字段出现在调用点传递，用 `extra=`：`candidate_id` / `work_id` / `job_id` / `source_type` / `provider` / `status` / `attempt` / `duration_ms` / `error_code` / `request_id`。所有字段都是可选，但为了让一个事件可以从一条日志跳到同一次操作的其他行，绕过它们是代价最高的习惯。

如果文件日志被启用但目录不可写（少见但会发生，比如数据目录被只读挂载），服务会以 `LOG_FILE_UNAVAILABLE` 警告为什么只走 stdout，不会拒绝启动。
