## 1. 目标与边界

**做**：让模型读一本书的元数据，输出这本书在书库里的相对路径（目录 + 文件名）。

**不做**（这一节是范围，越界即设计错误）：

- **不参与审批**。自动审批规则引擎（`app/auto_approval/`）不动，AI 不通过、不驳回、不评分。
- **不参与元数据**。不翻译标签、不改标题、不补字段、不决定 `{title}` 取日文还是英文。
  它读元数据，不写元数据。
- **不写 `ComicInfo.xml`**。落在 CBZ 里的元数据仍由 `app/conversion/comicinfo.py` 从同一份
  元数据生成，与本方案无关。
- **不覆盖人工决定**。「作品详情页手动指定的路径优先」这条策略在 R11 立下、R25 重申、
  R27 保留，本方案不动它：自动流程遇到 `is_manual=1` 一律让路（只有 R27 的「强制」才会覆盖）。

一句话：**AI 只代替「模板 + 规则」这一层，其余一切照旧。** 现有实现已经把所有落点收敛到
`ConversionService._library_target`（打包内，宽松）与 `planned_library_path` /
`planned_path_for_candidate`（操作员侧，严格）两处，AI 只是这条决策链上多出来的一环。

## 2. 互斥，以及默认模板去哪了

「模板 + 规则」和 AI 回答同一个问题——「这本书放哪」。同时启用就要定义谁先谁后，而
「AI 命中时用 AI、否则用规则」本身又是一套规则引擎。运营者要的是**换一种决定方式**，不是再加一种：

- 一个存档设置 `path_source`，取值 `template`（现状：默认模板 + 按条件匹配的模板）或 `ai`。
  **默认 `template`**：升级不动任何现有部署；而且 AI 模式需要先配置供应商，默认打开也不可用。
- **默认模板不消失，改名叫「兜底模板」**，且它的作用被本 v2 收窄：只有在运营者**显式打开**
  「AI 不可用时回退到规则匹配」（§7）之后才会被用到；默认情况下 AI 路径失败是进「需干预」。
- **规则列表在 AI 模式下不生效**，界面置灰并写明原因（§8），数据保留——切回 `template`
  立刻恢复，不需要重建。

## 3. 决策链：AI 插在哪一环

今天的顺序是「手动 pin → 模板/规则」，两个入口各自实现。本方案把它显式写死成一条链，
AI 是中间一环，两个入口共用同一份实现：

```text
1. 手动 pin（is_manual=1）            -- 自动流程永远第一，AI 不参与
2. 否则看 path_source：
   a. ai         -> AI 路径（带缓存，§4）
        模型链全部失败 -> 默认进「需干预」（§7）；勾了回退开关才用兜底模板/规则
   b. template   -> 默认模板 / 命中的规则模板（现状）
```

落地形态：新增 `ConversionService.ai_library_path(candidate_id, metadata, title)`，返回
`PurePosixPath | None`，与 `planned_path_for_candidate` 并排；`_library_target` 与
`planned_library_path` 各接一个分支，**不各写一份**。

## 4. 稳定与可重复：缓存即语义（本方案的核心）

模型不是确定性函数，而且一次路径决策要经过「供应商 → Key → 模型」三级选择。如果每次打包、每次
打开详情页、每次重新归档都现场问一遍，后果是：

- 详情页预填、打包落点、重新归档计划三处**互相打脸**；
- R27 的「一键重新归档」在 AI 模式下的判定依据是「路径有变动」，而每次重算都会变动 ——
  点一次按钮会搬动整个书库，下次还会再搬。

所以**必须有缓存，且缓存是语义的一部分，不是性能优化**：

- 新表 `ai_path_suggestions`（§11），主键 `candidate_id`，存**指纹**与**产出**。
- **指纹** = 哈希（送进模型的元数据 + prompt 全文 + 模型链（provider/model 顺序）+ 各 provider
  的 base_url）。**API Key 不进指纹**——轮询换 Key 不能让全库路径失效。
- 指纹相同 → 缓存命中，直接返回存下的路径，**不调用模型**。指纹变了（改了元数据、改了 prompt、
  换了模型链/地址）→ 这本书需要新答案。
- **调用点收敛为三类，渲染路径永不调模型**：
  1. 打包 job（`_handle_job`）——首次生成的绝大多数来源，天然在后台，复用现有超时/重试/失败上报；
  2. 「重新生成路径」显式动作（单件走即时调用，整库走后台队列）；
  3. AI 模式下的重新归档（§9，只对「需要新答案」的作品发起）。
  详情页预填、已下载列表、默认重新归档的**比较**都只读缓存：不产生网络请求、不产生延迟，
  更不会因为开一次页面就向第三方发出 N 条元数据。
- 因此第一次生成发生在打包时，**不写 pin**（沿用现状：打包只写 `artifacts.library_relative_path`），
  pin 仍只由人工改名/批量重排/强制重归档写入。

**判定「这本书不用动」的谓词（§9 复用）**：

```text
不用处理  =  缓存存在
          且 缓存.prompt_hash == 当前 prompt 哈希          （prompt 没变）
          且 缓存.relative_path == 当前记录在案的路径        （当前路径就是它产出的）
```

前一条排除了「换了 prompt / 换了模型链 / 元数据变了」，后一条排除了「路径被别的东西改过」
（人工改名、模板模式迁过来的、文件被移动过）。两条都成立 = 重新问一遍只会得到同一个答案，
所以**默认不纳入处理范围**（运营者可开关，§9）。

**这一节决定了一件事：缓存表不是「可选的加速层」，删掉它这套东西就是错的。**

## 5. 供应商与模型：多供应商、多 Key、主力 + 备用链

按运营者要求，AI 供应商**在设置里单独一页**管理（§8），不与路径模板混在一起。

- **供应商**（多条）：`名称`、`供应商编码`（协议适配器标识，目前只有 `openai`，预留将来的
  `anthropic` 等；同名唯一）、`基础 API 地址`、`启用`，以及超时/重试次数。
- **API Key**（每个供应商多条）：加密存储（与密码库同一套主密钥），可单独启用/停用、
  可加备注。**轮询**策略：
  - 每次请求从启用的 Key 里**轮转取下一个**（内存游标，重启从 0 开始，不追求精确计数）；
  - 遇到 `401/403` 视为**这把 Key 不可用**：本次换下一把，并给它一个冷却期（如 10 分钟）后跳过；
  - 遇到 `429` / 5xx / 超时：换下一把；`429` 同样给冷却期；
  - 一个供应商的 Key 全部试完 → 视为该**模型**失败，进入模型链的下一个。
  - 冷却状态落库（`cooldown_until` / `failures`），重启后不会立刻又撞同一把坏 Key。
- **可用模型名**（每个供应商一组）：页面可手填，也可以调 `GET /v1/models` 拉取后勾选。
- **模型链**（全局一条，有序）：**第 0 位是主力模型，其余是备用回退模型**。每一项是
  `(供应商, 模型)`——**按模型配置，不限制同属一个供应商**：主力用 A 家、备用回落 B 家是正常用法，
  也正是「主力坏了还有备胎」的意义。请求按顺序尝试，直到某一个返回可用的路径。
- **联通性验证（保存即验证）**：模型链条目不能凭手填直接生效。新增或修改一个
  `(供应商, 模型)` 之前必须先通过一次**真实请求验证**（§8.1），验证时间/结果/原因落库并显示在
  页面上；**未验证、或最近一次验证失败的条目不允许进链**。理由：地址写错、Key 无效、模型名
  不存在这三种情况在配置时最好发现，留到打包时才暴露就是一本已下载完的书卡在「需干预」。
  运行时某一条目失败仍按上面的 Key 轮询 / 模型链回落继续。
- 全链失败的处理见 §7。

## 6. 模型契约与默认 prompt

**输入**（一次请求一本书，JSON）：`japanese_title`、`english_title`、`artists`（数组）、
`groups`（数组）、`parody`（数组，原作，仅作系列名的参考）、`category`、`category_raw`、
`language`、`tags`（数组，截断到上限）、`page_count`。不送路径、不送候选 id、不送下载来源、
不送账号信息。作者/社团给**数组**而不是拼好的字符串，因为「一共几个人合作」本身就是判据；
`category_raw` 保留上游原文（`Doujinshi` / `Manga` / …），「是不是商业志」要从它读，不能在
翻译后的标签上猜。标签数量设上限，既是省钱，也避免把整份元数据塞进上下文。

**输出**（JSON 对象，两段）：

```json
{"directory": "社团名/作者名", "filename": "作品标题"}
```

- **分开收目录与文件名，`.cbz` 由本服务追加**——与 `plan_library_path` 今天 `f"{last}.cbz"`
  一致，不让模型决定扩展名。
- 模型不输出绝对路径、不输出 `..`；即便输出了也过不了 §7 的校验门。
- **prompt 由运营者自行配置**（路径设置页一个文本框），默认给一份参考 prompt 与
  「恢复默认」按钮。prompt 文本参与指纹（§4），所以改 prompt = 全库需要新答案。
- 元数据的投递方式：prompt 里可以写 `{{metadata}}` 占位符（就地替换为元数据 JSON）；不写占位符时，
  应用把元数据 JSON 作为**用户消息**追加在 prompt 之后。默认 prompt 用后者。
- **安全不依赖 prompt**：这段文本是可编辑的，所以「模型输出是路径」这件事的可信度完全靠 §7 的
  代码校验与清洗，而不是靠 prompt 里写没写「不要包含 `..`」。

### 6.1 默认参考 prompt（`ai_prompt` 的默认值，待运营者确认）

下面这段是默认值（点「恢复默认」回到它）。运营者可以直接改写，用不到的形态可以删掉；
**示例部分建议保留**，few-shot 对输出稳定性影响最大。prompt 全文参与指纹（§4），所以改一次
prompt = 全库需要新答案。

层级约定由运营者 2026-09-26 给定：**`刊发形式 / 社团 / 作者 / 系列名 / 作品名`**，缺的层直接省略；
**社团与作者都只有恰有 1 个时才成层**；文件名保留完整原题——文件名要能独立说明这本书，
分享或单独取用时不依赖目录；判断线索一般就写在标题里，所以先读标题，其余字段只用于确认。

```text
你是 EhBot 的书库整理助手。你会收到一部作品的元数据 JSON，请为它决定归档到书库中的相对路径。

只输出一个 JSON 对象，不要输出解释、Markdown 代码块或任何其它文字：
{"directory": "<相对书库根目录的目录，可多级，用 / 分隔>", "filename": "<不含扩展名的文件名>"}

归档层级固定为：刊发形式 / 社团 / 作者 / 系列名 / 作品名
其中社团、作者两层可以省略（缺失就整层不要，不要留空、不要写「未知」），
系列名与作品名两层一定存在。作品名是文件名，其余是目录。

判断线索一般就写在标题里：先读标题，artists 的人数、groups、category_raw、tags 只用于确认。
按下面顺序判断，命中即停。

一、刊发形式（第一层，必有一层）
  1. 活动发刊：活动名/届数一般写在标题里（如 "(C108)"、"[C108]"、コミケ108、例大祭、
     コミティア 等），照抄该活动名，例如 "C108"
  2. 杂志：标题里有刊名（快楽天、快楽天ビースト、COMIC 快楽天、メガストア 等）就用刊名
  3. 商业志：元数据表明是商业出版（category_raw 为 Manga 等非同人分类，或标题/标签注明）用 "商业志"
  4. 单行本：标题或标签表明是单行本（"単行本"、"tankoubon" 等）用 "单行本"
  5. 多作者的非单行本：用 "合作本"
  6. 单作者的非单行本：用 "同人志"
  7. 实在判断不了：单作者用 "同人志"，多作者用 "合作本"

二、社团（第二层，可省略）
  groups 恰好 1 个才加这一层；0 个或 2 个以上都省略（与作者同一规则）。多值不要写进目录，
  它们仍保留在 tags 与文件名里。

三、作者（第三层，可省略）
  artists 恰好 1 位才加这一层；0 位或 2 位以上都省略（合作本、合刊不列作者，多值保留在
  tags 与文件名里）。

四、系列名（第四层，必有）
  做法：去掉标题里下面这些部分，剩下的主干就是系列名
  - 作者/社团的方括号标注，如 [ぽりうれたん]
  - 翻译语言标注，如 [中文翻譯]、[中国翻訳]、[English]
  - 活动名，如 (C108)
  - 卷/话/文件号与标记，如 2、第7話、-File.7-、上/下、前編/後編
  例：[ぽりうれたん] 隣の喘ぎ声がうるさい2[中文翻譯] -> 系列名 "隣の喘ぎ声がうるさい"
  杂志例外：系列名 = 年月 + 特刊信息（刊名已经占了第一层，不要重复），
  如 "2026年6月号"、"2026年6月号 増刊"。
  系列名里不要出现刊发形式、作者、翻译语言。

五、作品名（文件名）
  保留完整原标题（文件名要能独立说明这是什么作品：分享或单独取用时不依赖目录信息）；
  把不能用于路径的字符换成空格：< > : " / \ | ? * 以及控制字符，
  去掉首尾的点与空格，不要用保留名（CON、PRN、AUX、NUL、COM1–COM9、LPT1–LPT9）。

通用规则：
1. 不要输出扩展名：.cbz 由程序追加。
2. 原文照抄：刊发形式、社团、作者、系列名、年月、活动名、作品名都用元数据原文，不要翻译、
   不要音译、不要缩写、不要自己创作。
3. 缺失的字段不要猜、不要编造；不确定就省略那一层，宁可路径短，也不要写不确定的信息。
4. 每一段尽量不超过 60 个字符，整条路径尽量不超过 180 个字符。
5. directory 不能以 / 开头，不能出现 . 或 .. 这两段；不要输出绝对路径、盘符、URL 或文件系统路径。

元数据字段：japanese_title（日文原名）、english_title、artists（作者数组）、groups（社团数组）、
parody（原作，仅作系列名的参考）、category、category_raw（上游分类原文，如 Doujinshi / Manga）、
language、tags（数组）、page_count。

示例：
输入：{"japanese_title": "[ぽりうれたん] 隣の喘ぎ声がうるさい2[中文翻譯]", "artists": ["ぽりうれたん"],
       "groups": [], "category": "同人志", "category_raw": "Doujinshi"}
输出：{"directory": "同人志/ぽりうれたん/隣の喘ぎ声がうるさい", "filename": "[ぽりうれたん] 隣の喘ぎ声がうるさい2[中文翻譯]"}

输入：{"japanese_title": "催眠性指導 -File.7-", "artists": ["左藤空気"], "groups": ["G-Power!"],
       "category": "同人志", "category_raw": "Doujinshi"}
输出：{"directory": "同人志/G-Power!/左藤空気/催眠性指導", "filename": "催眠性指導 -File.7-"}

输入：{"japanese_title": "快楽天 2026年6月号 増刊", "artists": [], "groups": [],
       "category": "漫画", "category_raw": "Manga"}
输出：{"directory": "快楽天/2026年6月号 増刊", "filename": "快楽天 2026年6月号 増刊"}

输入：{"japanese_title": "(C108) [サークルA] 夏の合同本", "artists": ["作者A", "作者B"],
       "groups": ["サークルA"], "category": "同人志", "category_raw": "Doujinshi"}
输出：{"directory": "C108/サークルA/夏の合同本", "filename": "(C108) [サークルA] 夏の合同本"}

输入：{"japanese_title": "○○の単行本", "artists": ["作者名"], "groups": [],
       "category": "漫画", "category_raw": "Manga"}
输出：{"directory": "商业志/作者名/○○の単行本", "filename": "○○の単行本"}
```

## 7. 校验与失败

模型给出的字符串会拼进文件系统路径，所以它和用户表单输入同级，但**处理方式与模板路径刻意不同**：
模板是运营者自己写的，`plan_library_path` 对非法段选择**拒绝**（让人去改）；AI 输出是生成的，而
「把标题变成合法段」这件事代码里本来就有现成的函数（`safe_library_name`，打包器一直用它），
所以 AI 路径是**清洗 + 拒绝**两条路：

1. 解析响应：先按 JSON 对象解析；失败时尝试抽取正文里第一个 `{...}` 对象（模型偶尔会加一句
   说明或代码块）。仍失败 → 失败。
2. 两个字段必须是字符串（`directory` 允许空串），文件名非空。
3. 按 `/` 拆目录段，逐段清理并拼回：

| 情况 | 处理 |
|------|------|
| 段里有 `<>:"/\\|?*`、控制字符、首尾点或空格、Windows 保留名 | `safe_library_name` 清洗（尽量保留原文），记 `ai_path_sanitized` |
| 段超过 `MAX_SEGMENT_LENGTH`（120） | `safe_library_name` 截断 |
| 某一段清洗后为空 | **整层省略**（社团/作者缺失就是这种情况） |
| 目录段出现 `..`、绝对路径或盘符 | **拒绝** `AI_PATH_INVALID`——这是穿越尝试，不是标点问题 |
| 清洗后文件名为空 | **拒绝** `AI_PATH_INVALID` |
| 整条超过 `MAX_RELATIVE_PATH_LENGTH`（240） | **拒绝** `AI_PATH_INVALID`（提示缩短） |

4. 追加 `.cbz`。
5. 真正落地前仍走 `_resolve_inside` 第二道门（现有实现，不在本方案里放宽）。

**失败链**：模型链的每一项（供应商 × 模型）都试过仍拿不到可用路径 —— 网络错误、鉴权失败、
超时、返回非法 JSON、被拒绝的路径都算失败 —— 之后：

| 设置 | 行为 |
|------|------|
| 默认（「AI 不可用时回退到规则匹配」= 关） | **进入「需干预」**：落 `CONVERSION_WAITING_PATH`，错误码 `AI_PATH_UNAVAILABLE`，消息写明「AI 供应商全部失败：<最后一次原因>」 |
| 打开回退开关 | 回落到兜底模板 / 规则，日志 `ai_path_fallback`，作品照常入库 |

- 为什么默认是需干预而不是回退：缺省静默换成模板路径，会让运营者以为 AI 生效了、其实是模板在
  跑，而路径一旦落库就变成既成事实。让书停住、把「AI 坏了」摆在待办列表上，是更诚实的默认。
- 需要干预的作品补救路径与 `CONVERSION_WAITING_PATH` 一致（修正/补齐后重新排队），UI 上多一句
  「检查 AI 供应商与 Key」。
- **不写缓存**：失败不落 `ai_path_suggestions`，否则一次网络故障会被固化成一本书的名字。

**操作员侧不撒谎**：详情页预填与重新归档的**计划阶段**遇到「没有缓存 / 缓存已过期」，不会现场
调模型，也不会展示兜底模板的答案——预填拿不到就不预填（表单保留原值），重新归档把这件归入
「需要新答案」并（视配置）入队，而不是悄悄展示一个打包器不会采用的位置。

## 8. 设置与界面

### 8.1 新页面：「设置 → AI 供应商」（`SETTINGS_AI`）

- **供应商列表**：名称、编码、基础地址、启用开关、Key 数量与可用状态、可用模型数，
  支持新增/编辑/删除（删除带确认）。
- **单条供应商编辑**：名称、编码（下拉，目前只有 `openai`）、基础地址、超时（秒）、重试次数；
  Key 子列表（新增/停用/删除，密文存储，**只显示末四位或备注，永不回显全文**）；
  可用模型子列表（手填 + 「从 `/v1/models` 拉取」按钮）。
- **模型链**：一条可拖拽排序的列表，第 0 位标「主力」，其余标「备用」；新增时选择
  `(供应商, 模型)`。页面顶部一句话说明失败顺序。
- **测试连接 / 验证联通性**：不是探活，也不是只列 `GET /v1/models`，而是用该 `(供应商, 模型)`
  发一次**最小的 chat 请求**（固定短文 + 要求回一个 JSON），因为要证明的不只是「地址通、Key 有效、
  模型在」，还有**它确实能按要求产出结构化输出**。回报四类之一：可用 / 鉴权失败 / 地址不可达 /
  模型不存在（含输出不可解析）。结果写入 `ai_provider_models.last_verified_*`，页面上显示
  「已验证 / 未验证 / 已失效（时间 + 原因）」。
- **保存即验证**：供应商保存时校验地址形状与至少一把可用 Key；模型链条目的新增/改动**必须先通过
  上述验证**，否则拒绝保存并说明原因——不能把「打包时才炸」的配置写进去。

## 9. AI 模式下的「一键重新归档」

R27 的按钮与结果面板保留，判定依据从「当前规则重算」换成「缓存 + 指纹」：

- **默认范围**：尚未成功归档的 + 缓存不存在或指纹已变（prompt / 模型链 / 元数据变了）的；
  以及缓存可用、只是记录路径与缓存不符的（当场移动，不调模型）。
- **默认不纳入**（`AI_ALREADY_CURRENT`）：满足 §4 谓词、即 prompt 未变且当前路径就是它产出的作品。
  这一条**只约束默认重排**——默认跳过；路径页的开关可以把它改成纳入（这是「让 AI 给同一本书换个
  名字」的入口）。
- **强制＝全库处理**（运营者 2026-09-26 确认）：忽略上面的跳过与「手动指定路径」，所有作品一律按
  当前 prompt 重新询问、按需移动。**已打包的作品仍然只移动、不重新打包**（R27 硬规则不变）；
  手动 pin 依然会被覆盖（与 R27 一致），覆盖后写 `is_manual=0`，之后改 prompt 还能再重排。
- **执行方式**：计划阶段绝不调模型。
  - 有可用缓存、只是路径与记录不符 → 当场移动（快，等同 R27 现状）。
  - 需要新答案 → 按 `每批处理数量` 入队一批「重算路径」的打包任务，由现有转换 worker 逐件处理
    （并发天然为 1，不引入第二套 worker）；模型调用发生在 job 内，复用现有超时/失败上报。
    `并发数` 只用于该任务内部的并发拉取（默认 2）；`使用流式` 服务于单件「重新生成」的实时预览，
    批量下只改变传输方式、不改变结果，默认关。
- **结果面板**：沿用 `queued / moved / unchanged / skipped`，skip 理由含 `AI_ALREADY_CURRENT`、
  `AI_PATH_UNAVAILABLE`；入队部分完成后由 `EVENT_CONVERSION` 驱动页面刷新（R27 同一机制）。
- **代价提示**：强制 = 全库 N 次模型调用（还要乘上备用模型的重试），提交前给出预估条数与二次确认。

## 10. 隐私、成本与可观测性

- **元数据会离开宿主机**。日文标题、社团、标签都会发给第三方。这是运营者的选择，必须
  **显式开启 + 页面明说**，并明确支持「本地/自托管 OpenAI 兼容端点」（Ollama / LM Studio）作为
  不外发的一种做法。README 与 `docs/USAGE.md` 要写上这一点。
- **Key 只进加密存储**，与密码库、种子客户端密码同一套主密钥；不写日志、不回显（页面只显示末四位
  或备注）。
- **成本**：每本书首次一次调用（含失败重试），之后缓存命中为 0；强制/重新生成是有意为之的
  一次性 N 次，页面上给出预估条数。
- **日志**：每次调用记一条结构化事件（`ai_path_suggested` / `ai_path_failed` /
  `ai_path_fallback`），带供应商、模型、Key 序号、缓存命中与否、耗时、结果码；与
  `archive_path_rule_matched` 同级，便于回溯「这本书为什么在这、是谁定的」。

## 11. 数据模型与设置键

- **迁移 `018_ai_path.sql`**（设置项仍走既有 `archive_settings` 键值表）：

```sql
CREATE TABLE IF NOT EXISTS ai_providers (
    id          INTEGER PRIMARY KEY,
    name        TEXT NOT NULL,
    code        TEXT NOT NULL,           -- 协议适配器，目前只有 'openai'
    base_url    TEXT NOT NULL,
    timeout_seconds INTEGER NOT NULL DEFAULT 30,
    max_retries INTEGER NOT NULL DEFAULT 1,
    enabled     INTEGER NOT NULL DEFAULT 1,
    created_at  TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at  TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS ai_provider_keys (
    id            INTEGER PRIMARY KEY,
    provider_id   INTEGER NOT NULL REFERENCES ai_providers(id) ON DELETE CASCADE,
    label         TEXT NOT NULL DEFAULT '',
    cipher        TEXT NOT NULL,          -- encrypt_password() 密文
    enabled       INTEGER NOT NULL DEFAULT 1,
    failures      INTEGER NOT NULL DEFAULT 0,
    cooldown_until TEXT,                  -- 401/429 后的冷却截止
    last_used_at  TEXT,
    created_at    TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS ai_provider_models (
    id           INTEGER PRIMARY KEY,
    provider_id  INTEGER NOT NULL REFERENCES ai_providers(id) ON DELETE CASCADE,
    name         TEXT NOT NULL,
    enabled      INTEGER NOT NULL DEFAULT 1,
    last_verified_at    TEXT,             -- 联通性验证（§8.1，保存即验证）
    last_verify_ok      INTEGER,
    last_verify_error   TEXT,
    UNIQUE (provider_id, name)
);

-- 有序：position 0 是主力，其余是备用回退。
CREATE TABLE IF NOT EXISTS ai_model_chain (
    position          INTEGER PRIMARY KEY,
    provider_model_id INTEGER NOT NULL REFERENCES ai_provider_models(id) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS ai_path_suggestions (
    candidate_id  INTEGER PRIMARY KEY REFERENCES candidates(id),
    fingerprint   TEXT NOT NULL,          -- 元数据 + prompt + 模型链 + base_url
    prompt_hash   TEXT NOT NULL,          -- §4 谓词用
    relative_path TEXT NOT NULL,          -- 已校验、已含 .cbz
    directory     TEXT NOT NULL,
    filename      TEXT NOT NULL,          -- 不含扩展名
    provider_id   INTEGER,
    model_name    TEXT NOT NULL,
    attempts      INTEGER NOT NULL DEFAULT 1,
    created_at    TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at    TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

- **新增 `archive_settings` 键**：`path_source`、`ai_prompt`、`ai_fallback_to_rules`、
  `ai_batch_size`、`ai_concurrency`、`ai_stream`、`ai_default_include_current`（仅约束默认
  重排；强制不受它影响）。
- **来源标注的判定**：存在 `ai_path_suggestions` 行且 `relative_path` 等于当前记录在案的路径
  → 标 `AI`。纯读、不加新列；人工改名后自然不再是 AI 路径（这是对的）。
- 缓存与 pin 的分工写进注释：**缓存是「模型层」的回答记录，pin 是「书库层」的落点权威**；
  两者都不是第二个真相——缓存只回答「同一份输入下模型说过什么」。

## 12. 测试与验收

- **单元**：目录层级的组装（刊发形式判定顺序、社团有则加、作者仅当恰 1 位、系列名去噪、杂志

  路径页 prompt 保存/恢复默认、回退开关、批量/流式/`include_current` 开关；打包真的落到 AI 路径；
  详情页预填来自缓存；`AI` 徽标；AI 模式下重新归档的默认/强制两档与入队行为；
  失败进「需干预」；缓存清除。

   Key**、可用模型列表；全局一条**主力 + 多个备用**的模型链。
2. 若用 AI 路径，**所有备用模型都试过仍无效 → 默认进「需干预」**；在路径设置页可勾选
   「AI 不可用时自动回退到规则匹配」。
3. 输出为**目录 + 文件名**两段。
4. prompt 由运营者在路径设置页自行配置，默认提供一份参考 prompt。
5. AI 模式**默认关闭**（需要先配置供应商，默认开启也不可用）。
6. 整库重排可配置**每批处理数量**（默认 20）、**并发数**（默认 2）、**是否流式**（默认关）；
   「prompt 未变且当前路径已是该 prompt 的产出」在**默认重排**里不纳入（可开关），
   **强制＝全库处理**，不受该开关影响。
7. 界面标注由 AI 生成的路径。
8. AI 仅用于决定打包后的存储位置。
9. **目录层级固定为 `刊发形式 / 社团 / 作者 / 系列名 / 作品名`**，缺层省略。**社团与作者同一规则：
   只有恰有 1 个时才成层**（0 个或 2 个以上都省略）。系列名去掉刊发形式/作者/翻译语言/卷号；
   杂志取「年月 + 特刊信息」（刊名已在第一层，不重复）。作品名**保留完整原题**（这样文件名能独立
   说明这本书，分享或单独取用时不依赖目录），只做路径字符清洗。
10. 刊发形式按「活动 → 杂志 → 商业志 → 单行本 / 合作本 / 同人志」判断，判据一般写在标题里。
11. 多值（多个社团、多个作者）**不写进目录**，信息由元数据与文件名承载。
12. 单本无卷号时系列名等于作品名、出现 `…/系列名/作品名` 的重复层级，这是「默认所有作品都是一个
    系列」的预期结果。
13. 全链失败进「需干预」时，分组里**显示触发的供应商/模型**。
14. 主力/备用**以模型为单位**配置，**可跨供应商**；**配置时必须验证服务联通性**（保存即验证，
    未验证或最近一次验证失败的条目不允许进链）。
