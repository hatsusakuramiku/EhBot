# R87 方案：WebUI 操作、实时连接与统一元数据编辑修复

**状态：已批准 v2，已实现（2026-10-13，R87）。** 运营者以「按这个方案动手罢」批准全部内容。
本文承接 R85/R86，覆盖七项问题。版本仍为 `0.3.0rc3`，迁移仍为 `025`。

**v2 已定需求：** 运营者明确要求通过 Compose 配置信任域名或 URL，示例为
`https://ehbot.mikufans.date`。本轮新增 `PUBLIC_BASE_URL` 作为公开访问地址，
WS 与 URL 生成据此工作；不要求运营者查 Docker 网关 IP 才能接通 WebUI。

## 1. 需求与验收目标

| 问题 | 交付后的行为 |
|---|---|
| 自动审核规则停用返回 405 | 页面表单提交到 Web POST 路由；启用/停用和同类规则动作均可局部更新 |
| WS 连不上、断线提示遮挡 | Compose 中配置公开 URL 后可通过 HTTPS 代理握手；顶栏左侧文字显示连接中、已连接、重连中或需要登录；断线自动重连，重连后自动校正当前内容 |
| 每页数量控件过窄 | 只保留每页 50 快捷项；取消 20/100/200，扩大自定义输入框；仍允许任意正整数 |
| 批量重新打包失败 | 实际页面勾选多件作品后可入队，局部更新执行状态；拒绝时展示具体原因 |
| 保存 ComicInfo 返回 Failed to fetch | 提交与重定向均保持浏览器同源；保存成功明确展示是否已经写回文件 |
| 元数据分成两套编辑 | 使用一个编辑区；未打包显示下次打包的值，已打包显示实际 ComicInfo 值；拉取更新非手动字段，已打包必须点击保存才改文件 |
| Cloudflare beacon 被 CSP 拦截 | 说明并处理代理注入的统计脚本；应用本身不引入外部统计脚本，不为消除报错放宽整个脚本策略 |

## 2. 当前证据与边界

诊断使用独立临时数据库、测试归档和真实 Uvicorn TCP 服务，没有访问运营者的业务数据或凭据。

**运营者补充的实际链路：** 浏览器 → Cloudflare 代理（小黄云）→ Caddy
`reverse_proxy` → EhBot 服务端口。公网 WS 地址为
`wss://ehbot.mikufans.date/ws/ui`，浏览器报告该地址连接失败。
运营者已确认 Cloudflare SSL/TLS 为 **Full (strict)**，EhBot 没有配置
`TRUST_PROXY_HEADERS`，因此代码默认不信任转发协议。Cloudflare→Caddy 为 HTTPS；
如果 Caddy→EhBot 为 HTTP，当前 Origin 判断就与浏览器的 HTTPS Origin 不一致。
该条件与本地握手 403 复现吻合，但尚未取得 Caddyfile 和 Caddy 实际回源的来源 IP。
运营者进一步确认：Caddy 在宿主机，EhBot 在 Docker 容器；Caddy 通常向
`127.0.0.1:已发布端口` 或 `localhost:已发布端口` 回源。这里的环回地址是
Caddy 的连接目标，不等于容器观察到的客户端来源。桥接网络和端口转发下，
容器可能看到 Docker 网桥网关或用户态代理的地址。这解释了原有 IP 配置的部署成本。
**此处原 v1 的“配置代理 IP 修复 WS”方案已被 v2 替代：** 配置 `PUBLIC_BASE_URL`
直接声明运营者认可的公网地址，不依赖容器观察到的源 IP 或代理转发头。
`TRUST_PROXY_HEADERS` / `TRUSTED_PROXY_IPS` 保留原有客户端 IP / 转发信息用途，
不是公开 URL 模式下 WS 的前置条件；仅在运营者主动启用代理头信任时继续要求 IP 配置。
2026-10-13 从本次执行环境匿名探测 `/login`、`/healthz` 和 `/ws/ui` 升级请求，
三者均收到 `server: cloudflare` 的 HTTP 502。该结果是当时的公开回源状态，
不能据此断言此前有认证的 WS 请求也是同一个故障；未登录 WS 本来就不应成功升级。

1. **405 已复现。** `app/api/settings.py` 和 `app/web/routes/auto_approval.py`
   都有名为 `toggle_auto_approval_rule` 的路由。设置模板的 `url_for` 得到
   `/api/v1/settings/auto-approval/rules/1/toggle`，表单 POST 到只支持 PUT 的 API 后返回
   `{"detail":"Method Not Allowed"}`。规则删除也存在同名问题，修复时一并覆盖这个相同根因。
2. **HTTPS 转发的 WS 403 已复现。** 用公网 Host、`Origin: https://ui.example`、
   `X-Forwarded-Proto: https` 连接内部 HTTP 服务：未信任代理时握手返回 403；
   只信任测试代理后能收到 `ready` 并执行读取命令。
   这证明配置与协议校验的边界，不证明运营者当前部署一定使用了错误配置。
   当前 `.env.example` 默认 `TRUST_PROXY_HEADERS=false`、`TRUSTED_PROXY_IPS=`。
3. **元数据保存的 HTTP 绝对重定向已复现。** Web `edit_metadata` 在内部 HTTP
   请求中返回 `http://ui.example/works/1?...`。从 HTTPS 页面 fetch 并跟随后会跨协议；
   浏览器可因混合内容或同源策略拒绝。模板中的绝对操作地址和静态资源地址也需检查。
4. **已打包编辑来源错误已复现。** 同一个真实 CBZ 中 `Title=File title`，数据库
   `Title=Database title`，编辑字段的 `field_value` 却使用后者。
5. **未改字段被覆盖已复现。** 仅 PATCH `Series` 后，文件的 `Title` 从
   `File title` 变成 `Database title`。当前写回重新生成整个映射，不能满足文件值为准的语义。
6. **批量操作尚未复现运营者的失败。** 使用实际 Jinja 页面、HTMX/Alpine/应用脚本的
   DOM 提交，按钮的 `action=repack` 和多个 `candidate_ids` 均到达 Web 路由，返回成功。
   不把“可能漏掉 action”当成已确认根因。还需覆盖连接成功时的 WS 提交、HTTP 降级、
   被拒绝的请求、按钮兼容性以及运营者的浏览器/代理条件。
7. **代码没有 beacon 引用。** 限定搜索 `app/`、`scripts/` 未找到
   `cloudflareinsights` 或 `beacon.min.js`；现有 CSP 只允许自身脚本。
   报错符合 Cloudflare 自动注入统计脚本被 CSP 阻止的情形，尚未读取实际 Cloudflare 配置。

临时诊断入口是 `.pytest_cache/r87_repro.py` 与 `.pytest_cache/r87_dom.cjs`；
它们不纳入产品或提交。实现时把有意义的案例移入正式测试，再清理临时诊断文件。

## 3. 修复设计

### 3.1 请求目标与失败反馈

- 为冲突的 API 路由设定独立名称，保持 HTTP URL 和方法；Web 名称保留给模板。
  同步命令发现目录及 API 文档中涉及的名称，避免移动端按旧名称猜测调用。
- 同源页面的操作、静态资源和重定向使用保留部署前缀的路径，避免从内部 HTTP
  协议拼出公网绝对地址。外部来源链接仍使用原地址。
- 表单提交尊重实际按钮的 `formaction`、`formmethod` 及 name/value。
  多选参数不能转成丢失重复值的对象；确认框中的外部 form 按钮也要覆盖。
- HTTP 与 WS 错误显示后端具体的拒绝、字段校验或跳过原因；JSON 422/405
  不能被当作 HTML 片段放进主内容区，也不能只显示“操作失败，请查看页面提示”。
- 写操作断线后不自动重发。先通过重连快照确认状态，再由运营者决定是否重新操作。

### 3.2 WS 握手与连接状态

- 新增 `PUBLIC_BASE_URL`，默认空字符串。运营者可以直接在其
  `docker-compose.yml` 的 `services.ehbot.environment` 中填写：

  ```yaml
  services:
    ehbot:
      environment:
        PUBLIC_BASE_URL: "https://ehbot.mikufans.date"
  ```

  项目实际已有 `compose.yaml` 和 `compose.deploy.yaml`，两者都同步接入这个配置，
  不增加第三份 Compose 文件。环境变量透传形式为 `${PUBLIC_BASE_URL:-}`，
  运营者使用自己命名的 Compose 文件时也可以直接填写上述字符串。
- 明确配置的公开地址是本服务的协议和 authority 真源。Cookie WS 的 Origin
  必须与其协议、域名和有效端口一致；`https` 对应 `wss`，`http` 对应 `ws`。
  域名大小写和默认端口规范化后比较，不接受子串、域名后缀或任意端口匹配。
  配置单个公开入口，不把 DNS 解析结果当作代理来源 IP。
- URL 使用完整 `http://` 或 `https://` 形式；域名配置通过 URL 中的 host 表达。
  允许末尾 `/`，拒绝凭据、查询串、片段及非法主机/端口。
  本轮公开地址配置只包含协议、域名和可选端口，部署子路径沿用 `APP_ROOT_PATH`。
  启动时验证，避免配置错误变成无限重连。
- HTTP/WS scope 中用于 URL 生成的公开协议与主机采用该固定配置；
  页面、API 契约和命令桥引用相同公开地址与现有部署前缀。
  不把浏览器 WSS 与容器的内部 WS/HTTP 协议混为一谈，不再因内部 HTTP 而
  错拒绝配置中的 HTTPS Origin，也不生成降级 HTTP 操作地址。
- 公开 URL 模式下无需设置 `TRUST_PROXY_HEADERS=true` 或 `TRUSTED_PROXY_IPS`。
  固定公开地址不会自动信任任意 `X-Forwarded-For` 或修改真实连接来源。
  原有代理 IP 配置继续用于明确需要可信转发信息的部署；空公开 URL 时保留
  当前直连/可信代理解析行为。Cookie、CSRF 和 Bearer 认证继续生效。
- 按 Caddy 的实际链路验证 WS 升级；当前 Cloudflare→Caddy 为 Full (strict)，
  Caddy→EhBot 已发布端口通常是 HTTP。Caddy `reverse_proxy` 自动处理升级，
  不要求为公开 URL 模式额外信任所有代理头。公开 502 仍需检查独立的回源端口、
  网络和服务可用性，填写公开 URL 本身不会修复代理无法连接上游的问题。
- CSP 的连接策略覆盖同源 WS/WSS；如目标浏览器不把 WS 识别为 `'self'`，只加入
  当前页面的明确 WS/WSS 地址，不使用允许任意主机的 `ws:`/`wss:` 通配。
- 保留已有退避重连、心跳和重连快照校正；顶栏左侧的小字替代固定提示卡片。
  正常时也显示“实时已连接”，断线显示“实时重连中”，移除“更新当前内容”按钮。
  认证失效明确显示需要登录，不能不断重试失效凭据。
- 后台事件局部更新，保留未保存输入、勾选、抽屉、焦点和滚动；不恢复页面状态轮询。

### 3.3 分页控件

- 候选、已下载共用的快捷项改为 `(50,)`。
- 自定义输入框提供足够宽度，允许在窄屏换行，不挤成只能看一两个字符的控件。
- 数量变更回到第一页，保留筛选、排序与重复参数；局部刷新仍不改变地址栏。

### 3.4 统一元数据编辑与保存

**一个编辑区，一份正在编辑的值。** 详情页和列表抽屉使用同一个服务端编辑快照。
不再分别提供“数据库元数据”和“归档文件元数据”两套编辑控件。

| 时点 | 展示与编辑的值 | 保存的效果 |
|---|---|---|
| 尚未打包 | 根据现有元数据映射得到的待写入值 | 保存有效更改，下次打包使用 |
| 已打包、刚打开编辑区 | 实际 ComicInfo.xml 的值；缺少字段显示为空 | 只保存本次明确更改的字段，不覆盖其他文件值 |
| 未打包、拉取完成 | 新拉取值覆盖非手动、非锁定字段 | 非手动拉取值可直接作为下次打包数据 |
| 已打包、拉取完成 | 在当前编辑区用新拉取值覆盖非手动、非锁定字段 | 显示待保存；拉取本身不改文件，点击保存后写回 |

- 手动更改和显式锁定都继续保护字段；锁定不是手动标记的重复项。
  上游字段映射到多个 ComicInfo 字段时，由服务端复用现有映射并应用这些保护。
- 手动输入与拉取填入分别记录来源。保存拉取结果不得把所有字段重标为手动，
  否则下一次拉取会失效。只把运营者实际输入的变化记录为手改。
- 已打包拉取产生的编辑草稿保留在当前编辑界面，并在实时片段替换时保留。
  重新进入页面仍以文件为准；数据库已取得的拉取内容保留，但不能冒充已经写回文件。
  本轮不增加跨会话草稿功能或额外草稿表。
- 显式保存允许“只有拉取结果、没有手动输入”的情况；不因缺少 `fields` 而拒绝。
  现有 PATCH 接口在需要时补充明确的保存参数，文档说明空改动与写回的区别。
- 保存已打包文件时，以当前文件为基准应用本次手动变化及待保存的拉取变化。
  不能再用整份数据库值重建并覆盖未编辑字段。`PageCount`、`Manga`、`Added`、
  图片成员及页结构继续保留；现有可编辑字段、文件边界和原子替换守卫继续生效。
- 文件损坏或不存在时给出明确读取错误，不静默用数据库值冒充实际文件值；
  打包正在执行时不与 worker 抢写。失败时保留编辑输入并说明是否写回文件。
- 移除第二块归档编辑区和“文件中的旧值”双值显示；原始抓取信息可保持只读。
  ComicInfo 映射与本服务保留的来源信息仍有不同用途，不能为合并界面而丢掉来源字段。

### 3.5 Cloudflare 脚本

默认解决方式是关闭该站点 Cloudflare Web Analytics 的自动脚本注入，
并在部署文档注明该设置与 WS 转发条件。EhBot 不需要外部统计脚本才能运行。
不加入任意外部脚本域、也不把这个 script-src 报错归因于 WS。
若运营者明确需要 Cloudflare 统计，再单独确认精确的 script/connect 域名策略；
当前不修改 Cloudflare 控制台，也不假定它已经关闭。

## 4. 实施顺序与验证

1. 修规则请求目标和同源路径 → 对页面实际生成的地址提交，确认 POST 成功、
   规则确实变为停用，HTTPS 场景不返回降级 HTTP 地址。
2. 修 WS 与连接提示 → 真实 TCP 服务覆盖直连/可信 HTTPS 代理/错误代理条件、
   配置 `PUBLIC_BASE_URL` 且不信任代理头的 HTTPS 入口、不同 Docker 来源 IP、
   匹配/非匹配 Origin、默认/自定义端口、URL 配置校验、公开地址生成、
   心跳空闲连接、关闭后自动重连、重连自动快照、认证拒绝和前缀部署。
3. 完整复验批量操作 → 实际页面多选后走 WS 与 HTTP，检查入队、局部状态更新、
   部分跳过、验证错误、确认框按钮；对尚不能复现的实际环境明确记录边界。
4. 统一元数据 → 真实 CBZ 覆盖文件与数据库不一致、只改一字段、未打包、
   拉取覆盖非手动字段、手动/锁定保护、拉取前后文件字节不变、显式保存后变化，
   以及损坏文件/运行中打包等守卫；验证图片、未改字段、路径和成员结构保留。
5. 调整分页与文档 → 验证每页 50 和自定义数量、重复筛选参数、窄屏布局；
   同步两份 Compose、`.env.example`、`README.md`、`docs/USAGE.md`、
   `docs/REALTIME_API.md`、相关需求与
   R87 阶段记录。定向测试、DOM 测试、collect-only、语法与 diff 检查分别报告。

只跑相关测试，除非运营者要求整库或发布。实现无需数据库迁移；如后续发现无法在现有模型下正确保存，
先修订本方案再决定迁移。本轮不修改 EhBot-Mobile；其后续实现复用同步后的接口。

## 5. 选择与取舍

- 采用共享请求边界与现有服务修复，避免每页单独补 fetch 或轮询。
- 采用明确的公开 URL 配置，直接满足 Compose 填域名/URL 的部署方式，
  不关闭 Origin 校验，不把公开域名解析成 Cloudflare IP 后充当代理 IP。
  保留原有代理 IP 配置的独立用途，WS 的公开 URL 模式不依赖它。
- 采用当前编辑界面保留草稿，不为本次缺陷增加跨会话草稿系统。
- 采用文件基准的明确字段更新，不用重新打包整个作品来保存 ComicInfo。
- 本方案批准后，代码、测试、方案和运营文档作为一个 R87 本地提交；
  不 push、不部署、不发布。
