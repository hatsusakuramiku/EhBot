{# 系统 tab: 主题、密度、并发上限、轮询间隔、时区. The tab has two halves that behave differently on purpose. 主题 and 密度 are per-browser, stored in `localStorage` and applied before the first paint by the inline snippet in `base.html`. They are not server state: one operator on a laptop and the same operator on a phone want different answers, and a stored server preference would make the phone wrong. So those two controls are the topbar's own segmented buttons, and this section only says where they live -- it does not render a second pair that could disagree. 并发上限, 轮询间隔 and 时区 are server state, read per job through a provider callable, so a save takes effect on the next task and nothing restarts. The bounds in the `min`/`max` attributes come from the same constants the service clamps with, so the form cannot offer a value the service would reject. `zoneinfo` has no tz database on every host this runs on, so the zone is validated by shape rather than against a list. The datalist below is a convenience for the common cases, not the set of legal values. #}
