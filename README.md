把 Telegram 频道里的漫画整理成规范的 CBZ 归档库。

服务盯着你指定的 Telegram 来源，把消息解析成**候选**；你在网页上审核，通过之后它才开始下载，
下载完解压、按 ExHentai 元数据补齐信息、打包成带 `ComicInfo.xml` 的 CBZ，按模板放进书库目录，
交给 Komga、Kavita 这类阅读器接管。

**范围止于归档。** 下载 → 转换成目标归档格式，外加少量便于操作的管理项（列表、批量重新打包、
移除、重新下载、改归档路径）。它不是书库管理器：没有阅读器、没有书架分组，也不会扫描不是本服务
下载的文件——那些交给下游工具。

主要能力：

- **统一元数据编辑**：未打包显示下次打包的值，已打包读取实际 `ComicInfo.xml`。拉取覆盖非手动、非锁定字段；已打包时先形成当前界面的草稿，点击保存才写回文件。只写本次更改，保留未改字段、图片、文件名和路径；非 ComicInfo 自定义字段只存数据库。移动端可复用相同 API。

- **审核先行**：下载需要先通过审核。支持批量通过/驳回与自动审批规则（类 SQL 条件：`LIKE` 通配符、`IN`、数值比较、标签集合，默认不区分大小写且可逐条开关）；每条规则选择**自动通过**或**自动驳回**，两类规则共用同一个规则池与同一条优先级队列（优先级小的先决定，一条候选只被一条规则决定）；可对历史候选试跑，后台按设定间隔自动跑；自动驳回的候选进入「已驳回」，可「重新排队」恢复。审核动作只有**通过**与**驳回**两种——「要求修订」已彻底移除，连历史审计行也一并清掉。
- **候选准入可控**：默认**只解析含 ExHentai / e-hentai 画廊链接的消息**——纯图片、压缩包附件、预览页消息在抓元数据之前就被忽略。「设置 → 解析规则」可逐项放宽（接受纯图片 / 压缩包 / 预览页、限定压缩格式），也就是把「什么样的消息算候选」写死在一个地方。
- **标题只来自画廊元数据**：作品名不再从 Telegram 文案里猜（旧版本把 caption 的首行当标题，反而压过画廊自己的名字）。加入候选后由后台抓取任务立刻读取画廊，取到名字就从「待补充」转入「待审核」；取不到就一直留在「待补充」等人处理——日语优先，网页卡片、归档文件名与自动规则看到的都是同一个名字，语言可在「设置 → 路径」的「标题来源」切换。列表在还没有标题时显示 `#<画廊 ID>`（没有画廊 ID 则显示 `候选 #<编号>`），只是显示，不会写进数据库。**活动页的卡片标题也改用作品名**（任务编号降为副行）。
- **一个画廊一件候选**：同画廊 ID 的合格消息复用统一处理记录或已有候选，保留各账号的来源，不重复建候选、运行 AI 或审批。无画廊 ID 时按可信原帖坐标或账号范围匹配，仍需人工审核，不由自动规则决定。
- **手动添加（仅 Eh 链接）**：只接受 ExHentai / e-hentai 画廊链接或 `telegra.ph/ehentai-<gid>-<token>` 预览链接。提交时先查重、再**真拉一次画廊**验证链接有效——画廊不存在 / 需要登录 / 网络失败都会停在表单并说明原因，**不建候选**；没有已启用的 EH 账号时按钮置灰、服务端也会拒绝并提示先保存、测试并启用账号。判重按画廊 ID（不管 token 怎么写）：已存在时不再建行，页面给出「作品已存在：候选 #N」的确认块与「跳转到该候选」按钮。添加成功即已审批并入队，元数据（含标题）在作品详情页可改或再拉一次。
- **搜索即过滤**：候选与已下载共用一个搜索框，`$…$` 里写条件、外面写关键词——`$tag:%ntr%$` 按标签模糊过滤、`$-tag:cosplay$` 排除、`$status:待审核$` / `$source:eh$` 按状态与来源过滤，`%`/`_` 是通配、`[%]`/`[_]` 是字面量，多个条件一律 AND；解析不了的片段分段退化成全局搜索并写明原因，搜索框下方把解析结果画成一排可点掉的 chips。**候选与已下载的标签**左键直接添加过滤条件，右键菜单选择过滤或排除；其他页面只显示标签。筛选、排序与分页在页面内更新，地址栏不变，标签带空格自动加双引号。候选与已下载列表可在页脚切换**每页条数**（仅保留每页 50 快捷项，默认 50；加宽输入框可手填任意正整数，无上限，换条数回第 1 页）。
- **一键去重**：已下载页提供「一键去重」，把同一画廊 ID 的多条历史候选（闸门生效前遗留的重复）合到一条：已完成打包的优先保留，其次页数较多者，再次最早入库者。执行前先逐组展示保留项与移除项；被移除的记录连同磁盘文件一并删除，仍有任务执行中的重复作品使用同一持久移除流程；业务记录先移除，停止与文件清理由后台确认。
- **AI 候选判定（默认关闭）**：先在「设置 → AI 供应商」配置模型，再到「设置 → 解析规则」手动开启。开启后每条解析出来的消息会先交给模型判断是不是一部作品，判定在解析规则**之前**执行，并可选择「AI 通过即完全覆盖解析规则」；模型整体不可用时有「拒绝 / 放行」兜底可选，默认拒绝。候选判定默认跟随全局默认模型，也可在本页单独指定一张「主力 + 备用」列表；**本页配置的模型全部失败时不会回退全局默认**，直接走兜底。只发消息正文、来源名称、链接与附件名，不发账号信息。
- **彻底删除**：候选详情页与候选列表都能把一条候选**连根删掉**——消息、元数据、审核历史、每个来源的下载任务与产物记录一并清除，并留一条审计记录；可选「连文件一起删」（已下载压缩包与已归档 CBZ），默认只删记录。来源规则也能批量启用 / 停用 / 删除 / 套用过滤规则，删除是**墓碑**：不再出现在列表里，也不会因为该会话再来消息而自动复活，重新保存同一来源即可恢复。
- **四级下载选路**：Telegram 用户账户（原档、免费、不受 20 MB 上限）→ Telegram Bot → ExHentai 种子 →
  telegra.ph 预览页，默认按「画质优先、成本其次」自动降级，顺序可在「设置 → 系统」自行调整。
  消耗 GP 的 ExHentai Archive Download 永不自动触发，只作手动按钮。
- **元数据以 ExHentai 为唯一权威源**，标签自动汉化，你手改过的字段可以锁定，不被后续刮削覆盖。
- **归档路径可控**：默认按 `{category}/{artist}/{title}` 模板生成；可在「设置 → 路径」配置按条件匹配的路径模板规则——命中规则的作品走该规则的模板，未命中走默认模板，作品详情页手动指定的归档路径始终优先。改完模板可用同页的「一键重新归档」让书库里已有的作品按新规则重排路径（已打包的作品只移动、改名，不重新打包；勾选「强制」则连手动指定的路径也一并按当前规则重算）。
- **压缩包都能读**：ZIP/CBZ、7Z、RAR（RAR3/RAR5，含 `-hp` 头部加密、固体包与 `.partN`/`.rNN` 分卷）都转成 CBZ；内置解压器只认少数 ZIP 方法，遇到 WinZip AES-256、Deflate64 这类会**自动改用随镜像安装的 7-Zip**，不再把「方法不支持」报成「密码错误」。7-Zip 不能用恢复记录修复损坏的 RAR 分卷，这是它唯一的能力缺口，文档里写明了边界。
- **安全默认**：解压前校验路径穿越、解压炸弹、图片魔数；凭据加密存储，页面不回显、日志不记录；
  移除记录时**默认不删文件**。
- **AI 生成归档路径（默认关闭）**：在「设置 → AI 供应商」按 AstrBot 式的两层结构管理模型。上层是
  多个 **OpenAI 兼容**端点（OpenAI、DeepSeek、OpenRouter、MiniMax，或本地 Ollama / LM Studio），一次可粘贴
  多把 API Key 轮询使用（401/403/429 自动冷却换下一把），并可填自定义请求头与供应商级默认参数；
  下层是从端点拉取或手填的模型清单，可批量启用 / 停用、逐模型覆盖请求参数。**请求体默认只发
  `model` 与 `messages`**，参数一律选填、按模型覆盖，因此拒绝 `temperature`、只认
  `max_completion_tokens` 的推理模型也能接入；配置**不做验证门槛**（「测试」是按钮，不是保存条件）。
  页面顶部是 **AI 功能总开关**，下面是「全局默认模型」——一张可跨供应商的有序链（第 0 位主力 + 备用
  回退），**其他页面不单独指定就用它**。控制链是 `总开关 → 各功能开关 → 该功能模型 → 全部失败不回退
  全局默认`：总开关关闭时任何功能都不调用模型（但**不删除**任何配置，重新打开即恢复）；「设置 → 路径」
  的「路径决策模型」与「设置 → 解析规则」的「候选判定模型」都可以选「跟随全局默认」或「本页单独指定」
  一条链，本页配置的模型全部失败时不会回退全局默认，交给该功能自己的兜底。把「归档路径来源」切成 **AI 生成**后，模型按元数据决定每本书的目录与文件名（模板与规则
  同时关闭，只作为可选的兜底）；答案按「元数据 + prompt + 模型链 + 请求参数」的指纹缓存，缓存命中时
  不发起任何请求。模型链全部失败默认停在「待定归档路径」等待处理，也可勾选回退到兜底模板。AI 生成的
  路径在作品详情页与已下载列表带 `AI 生成` 徽标。改了 prompt 或换了模型链之后，同页的「一键重新归档」
  会按新配置重排整个书库：**已打包的作品只重新询问路径并移动文件，不重新打包**；勾选「强制」即全库
  重新询问（含缓存已是当前答案的作品与手动指定的路径），提交前可先「试跑」看范围。同页还有「**自动添加系列**」开关（仅 AI 可用时有效）：打包时把系列名写进 ComicInfo 的 `<Series>` / `<LocalizedSeries>`——元数据里的「系列」优先，其次 AI 归档路径的所在文件夹名，最后才让模型判断并把结果写回元数据。
- **运行日志在页面上实时可看**：`/logs` 推送本进程的日志，可选级别下限（默认「信息」），
  不必为看一行报错去宿主机敲 `docker compose logs`。

界面按「工作台 / 候选 / 活动 / 已下载 / 运行日志 / 设置」六个域组织，单容器、单管理员、SQLite，无需外部数据库。

WebUI 共用一条 WebSocket 提交操作、接收状态与日志；重新打包、审核和设置操作局部更新，后台任务开始、进度、完成或失败自动反映在页面中。断线时保留内容并提示重连，不进行定时页面轮询；重连后校正快照，未确认的写操作不自动重发。HTTP API 和普通表单保留。移动端后续接入同一协议，详见 [实时 API 契约](docs/REALTIME_API.md)。R87 交付源码，未发布新镜像；连接状态在顶栏左侧显示，断线自动重连并校正内容。

**关于数据外发**：启用 AI 路径模式后，作品的元数据（标题、社团、作者、标签等）会被发送到你在
「AI 供应商」里配置的端点，由该端点按元数据决定存储位置与文件名；启用 **AI 候选判定**后，监听到的
消息正文、来源名称、链接与附件名会被发送到该功能当前生效的模型端点，用于判断这条消息是否是候选。两者都是
显式选择、都默认关闭，不配置任何供应商时不会有任何外发；使用本地/自托管的 OpenAI 兼容服务
（Ollama、LM Studio 等）则这些内容不离开宿主机。API Key 与归档密码一样加密保存在 `data/private/`
下，页面不回显、日志不记录。

## 部署（推荐 Docker）

镜像已发布到 Docker Hub，部署机不需要源码，也不需要 Python 或构建工具链。

**1. 建一个目录，放入 `compose.yaml`：**

```yaml
services:
  ehbot:
    image: hsmk/ehbot:latest
    container_name: ehbot
    init: true
    restart: unless-stopped
    ports:
      - "8080:8080"
    environment:
      TZ: "Asia/Shanghai"
    volumes:
      # 数据库、会话密钥、加密密码库、7-Zip 安装。丢了就要重录所有凭据，务必保留。
      - ./data:/app/data
      # 打包好的 CBZ 落点，交给 Komga/Kavita 读取。
      - ./library:/library
      # 解压工作目录；若用 qBittorrent 下载，这里要能读到它的完成目录。
      - ./work:/work
```

**2. 启动并取初始密码：**

```powershell
docker compose up -d
docker compose exec ehbot cat /app/data/bootstrap_admin_password
```

**3. 打开 `http://127.0.0.1:8080`**，首次账户名 `admin`，输入账户名和上述私有文件中的一次性密码。
也可在宿主机读取 `data/bootstrap_admin_password`；启动日志只提示文件位置，不打印密码。登录后必须先改密码才能用其他页面；改完该文件即被删除。
只要没改过，每次重启都会重新生成一串新的。

**4. 在「设置 → 外部连接」添加账号配置，填写并保存 Telegram Bot Token 或 ExHentai Cookie，测试后启用**（只想用账户收消息的话，
只登录 Telegram 用户账户也能自动摄取；两者都配置则并行运行、自动去重），再到「设置 → 来源规则」
选择监听账号并添加要监听的频道——不知道 Chat ID 就先选择已启用的 TG 用户账号，再点「读取我的频道与私聊」，列出该账号所在频道、
群组与私聊的 ID，可勾选多条一次加入（默认停用，确认过滤规则后再启用），不必等消息到达后才知道。
「设置 → 解析规则」决定哪些消息会被解析成候选，默认只收含画廊链接的消息。凭据存在 `data/private/` 下；保存后默认显示掩码，可显式显示、隐藏或修改，TG 登录会话不提供导出。停用保留配置与会话，重启不会自动启用已停用账号；修改凭据或删除先等待旧监听、请求和远端资源确认停止。多端修改要求账号版本和幂等键，冲突不会覆盖另一端的新配置。

会话签名密钥首次启动自动生成，不用手工创建任何秘密文件。仓库里的 `compose.deploy.yaml` 是一份
带完整环境变量注释的参考，可直接抄。

HTTPS 反向代理入口在 Compose 的 `services.ehbot.environment` 配置公开地址：

```yaml
PUBLIC_BASE_URL: "https://ehbot.mikufans.date"
```

`compose.yaml` / `compose.deploy.yaml` 也可从 `.env` 读取该值。它固定 HTTP/WS 的公开协议、域名和可选端口，
无需配置 Docker 网关 IP；子路径仍用 `APP_ROOT_PATH`。只允许 HTTP(S) origin，不包含凭据、路径、查询或片段，错误配置在启动时拒绝。
空值保留直连/原可信代理行为；不改变实际客户端 IP，也不自动信任 X-Forwarded-For。
`TRUST_PROXY_HEADERS` / `TRUSTED_PROXY_IPS` 保留独立的可信代理用途，默认 false / 空。
宿主机 Caddy 的 `reverse_proxy 127.0.0.1:已发布端口` 自动支持 WebSocket Upgrade。
使用 Cloudflare 时保持 Full (strict)，关闭该站点 Web Analytics 自动注入，避免其 beacon 脚本与本应用 CSP 冲突。
若代理返回 502，还需检查 EhBot 是否启动及 Caddy 回源端口是否可达，公开地址配置不会修复上游不可达。

### Windows 上的注意事项

Windows 宿主机运行时，服务会下载固定版本的官方 7-Zip Windows 安装包和
`7zr.exe`，校验两份 SHA-256 后仅将便携的 `7z.exe` 与 `7z.dll` 解到
`data/tools`。它不会运行安装程序，也不读取 `PATH`、注册表或
`Program Files` 中的系统 7-Zip。

正式部署仍建议使用 Docker；如果在 Windows 上使用 Docker：

- 安装 Docker Desktop 并启用 WSL 2 后端。
- **把绑定目录放在 WSL 文件系统里**（例如在 `\\wsl$\...` 下建目录），而不是 `C:\Users\...`。
  跨 `/mnt/c` 访问会让解压和打包慢一个量级，`data/` 里的 SQLite 也可能因文件锁差异出问题。
- Windows 上不需要设置 UID/GID。Linux 宿主若当前用户不是 `1000:1000`，则要在 `.env` 里改
  `EHBOT_UID` / `EHBOT_GID`，否则绑定目录不可写。
- 用 PowerShell 跑上面的命令即可，路径分隔符照写 `/`。

### 其他部署方式

从源码构建（需要 Docker 引擎）：

```powershell
git clone https://github.com/hatsusakuramiku/EhBot.git
cd EhBot
Copy-Item .env.example .env
docker compose up --build -d
```

不用容器直接跑（仅建议在 Linux 上，或用于开发）：需要 Python 3.12 与 `uv`。

```powershell
python -m uv sync
python -m uv run uvicorn app.main:app --reload
```

访问 `http://127.0.0.1:8000`。存活与就绪检查分别是 `/healthz` 与 `/readyz`。

### 升级

```powershell
docker compose pull
docker compose up -d
```

数据库迁移在启动时自动执行，只追加不回滚。`data/` 与 `library/` 是绑定目录，重建容器不会动它们。

## 移动客户端与 API 鉴权

手机端是一个独立的 Flutter 仓库（`ehbot-mobile`，与本仓库平级），只通过本服务的 `/api/v1`
通信。客户端支持两种登录：

- **密码登录**：用管理员账户名＋密码换取一对令牌——access（默认 12 小时，过期由客户端自动续期）
  与 refresh（默认 30 天，每次刷新都会轮换）。改管理员密码会吊销所有密码登录的令牌，其它设备需要重新登录。
- **API Key 登录**：在网页「设置 → 密码库 → API 密钥（移动端）」手动生成，粘贴进客户端。
  全局**同时只有一条有效 Key**；它**不过期**，**刷新会让旧 Key 立即失效**，改管理员密码**不影响**它。
  明文只在生成那一次显示，之后页面只留标识与最近使用时间。

「设置 → 密码库 → 管理员账户」可修改账户名，始终只有一个管理员。改名保留已登录设备；各设备独立登录、注销。
改密码会使其他浏览器、密码令牌和相关 WS 失效，发起操作的浏览器保留登录。管理员配置提交携带版本号，旧版本返回冲突，避免多端覆盖。
升级到 schema 026 后旧浏览器 Cookie 需重新登录；密码 API 登录也必须传 `username`，不再支持仅密码请求。

令牌有效期可在「设置 → 系统」调整（60 秒 – 365 天）。REST 入口是
`POST /api/v1/auth/login|refresh|logout` 与 `GET /api/v1/auth/whoami`；其余 `/api/v1` 端点同时接受
浏览器会话与 `Authorization: Bearer <凭据>`，Bearer 请求不需要 CSRF。默认不生成 API Key，全新部署
只有密码登录可用。
